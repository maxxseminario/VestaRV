# RISC-V ISA Verification Tests

This directory contains instruction-level tests for verifying the Vestarv RISC-V processor implementation.

## Directory Structure

```
verification/isa/
├── tests/              # Test source files
│   ├── rv32ui/        # User-level integer instructions
│   ├── rv32um/        # Multiply/divide extension
│   ├── rv32ua/        # Atomic extension
│   ├── rv32uc/        # Compressed extension
│   ├── periph/        # Peripheral tests
│   ├── boot/          # General purpose boot code
│   └── ...
├── build/             # Build artifacts (auto-generated by make)
│   ├── rv32ui/        # Compiled tests for rv32ui
│   │   ├── *.elf     # Test binaries
│   │   ├── *.dump    # Disassembly files
│   │   ├── *.rcf     # RCF files for VHDL simulation
│   │   └── *.bin     # Raw binary files
│   └── ...
├── rcf/               # Collected RCF files from all test suites
│   └── *.rcf         # All RCF files in one location for VHDL testbench
├── macros/            # Test macros and helpers
└── Makefile           # Build system

```

## Building Tests

### Build Specific Test Suite

```bash
make rv32ui      # Build all RV32I user-level integer instruction tests
make rv32um      # Build all multiply/divide tests
make rv32ua      # Build all atomic instruction tests
make periph      # Build peripheral tests
```

### Build All Tests

```bash
make all
```

## RCF Files for VHDL Simulation

RCF (RAM Configuration Files) are generated automatically when building tests. These files are formatted as binary strings (32 bits per line) and are used to initialize memory in VHDL testbenches.

**Key Features:**
- All RCF filenames in a test suite are automatically padded to the same length using 'x' prefix
- This ensures VHDL can iterate through them using consistent string lengths
- Files are organized by test suite in `build/<suite>/`
- **All RCF files are automatically collected in the `rcf/` directory for easy VHDL access**

**Example:**
```bash
make rv32ui
ls rcf/*.rcf  # All rv32ui RCF files are now in rcf/
# Output: xxxxrv32ui-p-add.rcf, xxxxrv32ui-p-sub.rcf, ...

make periph
ls rcf/*.rcf  # Now includes both rv32ui and periph RCF files
```

**VHDL Integration:**
Point your VHDL testbench to the `rcf/` directory:
```vhdl
-- Example: Load RCF file from central rcf directory
file_path := "rcf/xxxxrv32ui-p-add.rcf";
```

**Collecting RCF Files:**
- `make <suite>` - Automatically collects RCF files to `rcf/` after building
- `make collect-all-rcf` - Collect all existing RCF files from all build directories

## Available Test Suites

Use `make list-suites` to see all available test suites:

- **rv32ui** - User-level integer instructions (ADD, SUB, AND, OR, XOR, etc.)
- **rv32um** - Multiply/divide extension (MUL, MULH, DIV, REM, etc.)
- **rv32ua** - Atomic extension (LR, SC, AMO operations)
- **rv32uc** - Compressed instruction extension
- **rv32uf** - Single-precision floating point
- **rv32ud** - Double-precision floating point
- **periph** - Peripheral-specific tests
- **boot** - Boot sequence tests
- **spifem** - SPI flash tests

## Listing Tests

List all tests in a specific suite:
```bash
make list-tests-rv32ui
make list-tests-periph
```

## Cleaning

```bash
make clean-rv32ui    # Clean only rv32ui build artifacts (keeps rcf/)
make clean-periph    # Clean only periph build artifacts (keeps rcf/)
make clean-all       # Clean all build artifacts and rcf/
make clean           # Full clean (same as clean-all)
```

**Note:** Individual suite cleaning (e.g., `make clean-rv32ui`) only removes that suite's build directory but keeps RCF files in `rcf/`. Use `make clean-all` to remove everything including `rcf/`.

## VHDL Integration

Point your VHDL testbench to the `rcf/` directory where all RCF files are collected:

```vhdl
-- Example: Load RCF file from central rcf directory
file_path := "rcf/xxxxrv32ui-p-add.rcf";

-- Or iterate through all tests in rcf/
-- All files have consistent name lengths for easy string manipulation
```

The consistent filename length and centralized location make it easy to iterate through tests in VHDL.

## Requirements

- RISC-V GCC toolchain (`riscv-none-elf-gcc`)
- See `../../tools/build/README.md` for toolchain setup instructions

## Test Format

Tests are written in RISC-V assembly (`.S` files) and follow the standard RISC-V test framework conventions:
- Tests use macros from the `macros/` directory
- Each test checks specific instruction behavior
- Tests report pass/fail via special memory writes

## Memory Layout

Tests are configured to run at specific memory addresses matching the Vestarv memory map:
- Test code starts at offset `0x4000` (default)
- Configurable via linker scripts in `../env/p/`
