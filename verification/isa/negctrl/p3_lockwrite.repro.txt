----------------------------------------------------------------------------
p3_lockwrite_seed.patch — hdl/common/vesta/csr_unit.vhd
----------------------------------------------------------------------------
Makes `pmp_locked()` return false unconditionally. That function's ONLY
consumers are the sixteen per-byte lock filters in the four CSR_PMPCFG write
arms, so the seed drops EXACTLY the "a locked entry's cfg byte is
write-ignored until reset" rule (p0_specs.md 4.1) and nothing else: pmpaddr
locking goes through `pmp_addr_writable()`, which reads own_cfg(7) directly
and is untouched. The failure is therefore isolated to cfg immutability, and
privpmpcs CHECKs 41/42/43 (pmpaddr12 immutable, pmpaddr13 TOR-locked by entry
14, pmpaddr14 immutable) still pass under the seed — which is what makes this
a control for the cfg half specifically.

privpmpcs CHECK 37 arms the locks in one pmpcfg3 write
(e12 = 0x9B L|NAPOT|W|R, e13 = 0x0B TOR|W|R, e14 = 0x89 L|TOR|R, e15 = 0x00)
and CHECK 38 then writes ALL-ZEROS to pmpcfg3. Fixed, only the UNLOCKED bytes
clear and it reads back 0x0089009B (this single check pins BOTH the
locked-byte immutability AND the per-byte filtering: a whole-word lock would
read 0x00890B9B, a missing lock 0x00000000). Seeded it reads 0x00000000 and
the bounded `bne` fires at t4 = 38.

Exact repro (from the repo root; privpmpcs is an ON-ONLY test)
----------------------------------------------------------------------------
The ON hardware is a `make chip` product, not a hand edit. The test arms are
selected by the phase-standard EXPLICIT-APPEND dispatch (all three -D flags
appended to RISCV_GCC_OPTS, never auto-derived from a header).

  ON_OPTS="-static -mcmodel=medany -fvisibility=hidden -nostdlib -nostartfiles \
           -DNHARTS=4 -DCORE_ENABLE_TRAPCSR -DCORE_ENABLE_UMODE -DCORE_ENABLE_PMP"

  # 0. Keep a copy of the committed default MemoryMap.vhd to restore later
  cp hdl/common/MemoryMap.vhd /tmp/MemoryMap.vhd.default

  # 1. Stage the ON hardware (generated, four-constant delta vs the default)
  echo '{"priv": {"trapCsr": true, "umode": true, "pmp": true}}' > /tmp/p3_on.json
  cd platform/common/python && CHIP_CONFIG=/tmp/p3_on.json python3 generate.py
  cp ../out/hdl/MemoryMap.vhd ../../../hdl/common/MemoryMap.vhd
  cd ../../..
  grep -n "CORE_ENABLE_PMP" hdl/common/MemoryMap.vhd     # must read := true

  # 2. Build the ON-arm images (only the rv32ua group carries the -D flags;
  #    xcelium/riscv_test/rcf must stay a SYMLINK to verification/isa/rcf)
  cd verification/isa && rm -rf build/ && make rv32ua-flash RISCV_GCC_OPTS="$ON_OPTS"
  cd ../../xcelium/riscv_test/behavioral_mp
  ./xrun_batch.sh rv32ua-p-privpmpcs                 # expect: TEST PASSED
  # (never pipe xrun_batch through `head` — SIGPIPE leaves a STALE xrun.log;
  #  always confirm the "Starting test:" line names your test)

  # 3. Apply, re-run (RTL-only seed, no image rebuild), revert, re-run
  cd ~/vestarv && git apply verification/isa/negctrl/p3_lockwrite_seed.patch
  cd xcelium/riscv_test/behavioral_mp && ./xrun_batch.sh rv32ua-p-privpmpcs
  grep -E "TEST PASSED|TEST FAILED" xrun.log          # expect: TEST FAILED
  cd ~/vestarv && git apply -R verification/isa/negctrl/p3_lockwrite_seed.patch
  cd xcelium/riscv_test/behavioral_mp && ./xrun_batch.sh rv32ua-p-privpmpcs
  grep -E "TEST PASSED|TEST FAILED" xrun.log          # expect: TEST PASSED
