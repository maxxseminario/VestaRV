# V4 multi-hart lockstep sweep list — the sh* (SH-MULTIHART) suite.
#
# Use with:  MULTIHART=1 COSIM_BOOT=1 BRACKET_ISR=1 \
#              TESTS_FILE=cosim_sh_tests.txt ./xrun_cosim.sh
#
# BRACKET_ISR=1 IS REQUIRED for this list, not optional. A hart-0 legacy meip
# trap (cause=8000007f tval=00008154 -> IVT slot 85) is reported as a
# control-flow divergence without hart-0 ISR bracketing, and the cell is a FALSE
# DIVERGE. shafe was the founding case; shirq/shwfi carry the same shape and are
# still on the list, so the flag stays REQUIRED. Tile harts are bracketed
# unconditionally (Amendment A11 - the park window is in their stream by
# construction).
#
# CPR8/R7 (2026-08-15): the shipped chip is FIVE harts, so MULTIHART=1 now
# expands to COSIM_HARTS="0 1 2 3 4" and this list is 16 tests x 5 harts = 80
# cells. It was 17 x 4 = 68; see the shafe entry below for the one row that
# left.
#
# One rcf basename per line; blank lines and #-comments are ignored. Every entry
# is 22 chars so that "../rcf/" + name is exactly the 29-char TEST_FILE generic.
#
# Staged per ~/vesta_docs/lockstep/v4_design.md §4.9/§4.10. Classification is by
# MECHANISM, mechanically censused from the sources. The stage order is
# simplest-first so that each stage adds ONE new piece of machinery.
#
# WHAT LOCKSTEP DOES NOT PROVE HERE (v4_design.md §4.8 — read before quoting a
# pass): each hart's own architectural stream is compared; inter-hart ORDERING,
# ATOMICITY (AMO grant-locking, mutex claim, resv_unit's SC adjudication) and
# MUTUAL EXCLUSION are taken as TRUE by construction, because every shared load
# is defined by what the RTL itself returned. "The sh* tests pass lockstep" is
# NOT "the shared window is verified".

# ── Stage 1/2 · class A — hart-0-only (tiles stay parked; no new mechanism) ───
xxxxrv32ui-p-shmem.rcf
xxrv32ui-p-shclint.rcf

# ── Stage 2 · class C — plain shared stores + loads ───────────────────────────
# First use of PLANT + the sleep bracket + G (register replay).
# shboot is the cleanest bracket test in the tree: its subject IS the loader.
# NOTE shmem_mp carries finding T1 (rtl_findings.md): its three tiles never
# reach tile_body (launch margin 1,011 cycles vs 32,768 needed). They are
# expected LAUNCHED-ONLY -- they DO take the loader trap and copy ~33 of 4096
# words, they just never arrive, so they are NOT coverage. (Pre-C3 the audit
# called them PARTICIPATED, because the IVT slot jump at 0x814c alone satisfied
# the old "any retire at pc >= 0x4000" rule.) Ruled run-as-is in V4 (V4-7); do
# not "fix" the test here.
xrv32ui-p-shmem_mp.rcf
xxxrv32ui-p-shboot.rcf
xxxrv32ui-p-shuart.rcf

# ── Stage 3 · classes D+E — LR/SC and AMO. THE VALUE CASES. ──────────────────
# Three of the five historical core-bug post-mortems live here (M4b's SC
# premature write + SC-addr-via-PASS-B, M8's AMO dispatch phantom read).
# Adds F (forced SC failure). The SC success/failure DECISION is asserted, not
# compared; the SC's address, its rd, and outcome/effect consistency ARE.
# shlrsc first (smallest: 5 lr / 6 sc), then shcount (measured 4-hart live).
xxxrv32ua-p-shlrsc.rcf
xxrv32ua-p-shcount.rcf
xxxrv32ua-p-shspin.rcf
xxxrv32ua-p-shlock.rcf
xxxxrv32ua-p-shamo.rcf

# ── Stage 4 · class F — claim-based (side-effecting READS) ────────────────────
# Mutex-bank claim reads arbitrate roles. Served by the existing MMIO replay, so
# the mutex bank is taken as true four times over: shmutex passing lockstep says
# NOTHING about mutual exclusion.
xxrv32ui-p-shmutex.rcf
xxrv32ui-p-shtimer.rcf
xrv32ui-p-shperiph.rcf
xxxxrv32ui-p-shi2c.rcf

# ── Stage 5 · class G — sleep / IPI / mid-test re-park (ATTEMPT, per V4-6) ────
# Needs NESTED sleep brackets + the meip inject partition. Highest machinery,
# lowest incremental value. Stopping after Stage 4 is pre-authorised IF Stage 5
# proves disproportionate — but if we stop, the residue text must say plainly
# that meip-driven interrupt lockstep remains UNDEMONSTRATED PROGRAM-WIDE.
# RESULT 2026-07-30 (C3): Stage 5 RAN AND PASSED 12/12. Nested brackets work on
# real workloads (2 brackets per re-park cell, up to 32,850 records bracketed
# out) and the meip inject partition delivered: shafe hart 0 brackets four
# src=85 (meip) windows, so meip-driven interrupt lockstep is DEMONSTRATED
# rather than residue. The V4-6 "stop after Stage 4" authorisation was not used.
xxxxrv32ui-p-shwfi.rcf
xxxxrv32ui-p-shirq.rcf
# ── shafe · REMOVED AT CPR8/R7 (2026-08-15), on a MEASUREMENT ────────────────

# and not an RTL regression -- the test is N<=4 by construction. Its successor
# is `shorch`, which is excluded from THIS list for the ordinary reason below.
# Stage 5's meip-bracket result stands on the record; it was measured on shafe
# at N=4 and nothing about it is retracted.

#   aperture's backing bytes where the DUT returns another hart's TCM (and
#   ZEROS for a gated tile, which no memory model reproduces). R6 excludes
#   aperture-reading tests from the standing lockstep lists for that reason

#   and it is PERMANENT, not a staging decision. shorch is excluded for the
#   ordinary reason instead: it is a new multi-hart mechanism (AFE stub bank +
#   hart-0 demux + msip hand-off) that has never been staged through the V4
#   class ladder, and adding an unstaged mechanism to a standing gate is how a
#   false DIVERGE becomes a pin.
