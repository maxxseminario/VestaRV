# cosim_xallow.txt — the Amendment A9 x-wildcard allowlist (V3, 2026-07-30).
#
# Consumed by tools/cosim/compare.py --x-allow. One `<pc> <addr>` pair per
# line, lowercase 8-hex, #-comments ignored. For a record whose pc (an `R`) or
# addr (an `M`) appears here, an `x` nibble in the RTL field compares as a
# WILDCARD; every DEFINED nibble is still compared exactly and the field width
# must still match. Records NOT named here keep Amendment A5's exit-4
# INVESTIGATE behaviour unchanged.
#
# THIS FILE IS THE OPERATIONAL FORM OF RULING A2: refuse x-tainted records by
# default, permit a NAMED one only with its rationale written down and its use
# COUNTED. compare.py prints an application census on every run ("x-wildcard
# applied N application(s) across M record ident(s)"), so an entry that starts
# firing more often than its rationale predicts is visible in the run log
# rather than silently absorbing new taint. It is NOT a "skip x" switch.
#
# Both entries below are needed only for BOOTROM-INCLUSIVE runs (COSIM_BOOT=1).
# In the entry-aligned V2/V3 default they are pre-entry and never compared.
#
# ---------------------------------------------------------------------------
# ENTRY 1 — GPIO0 PxIN read of undriven input pads
#   pc   0x00000070  `lw x14, 0(x11)`   (encoding 0005a703)
#   addr 0x00004000  GPIO0 PxIN
#   Observed:  rdval / L-data = 000000bx   (bit 0 undriven)
#   Rationale: the boot ROM reads the strap/pad byte and IMMEDIATELY masks it
#   (`andi a4,a4,0x80` on the next instruction), so the undriven bit cannot
#   reach architectural state. v1_report.md §8.2 classifies it as benign and
#   as neither a tracer bug nor an RTL bug: undriven input pads in a
#   behavioural sim have no defined level. Verified stable across two runs
#   (byte-identical traces, V3 checkpoint 3).
#   PC RE-PINNED 0x00000070 -> 0x0000005c (2026-08-23). The boot ROM was flipped
#   rv32i -> rv32ic (software/bootrom_mp/isa.bzl), .text 10,140 -> 7,376 bytes,
#   so every instruction ahead of this one re-encoded and this read MOVED. The
#   read itself did not change: same GPIO0 PxIN at 0x4000, same 000000bx, and
#   the very next instruction is still the `andi a4,a4,128` the rationale above
#   rests on -- only the ENCODING is now the 16-bit `4198` instead of the 32-bit
#   `0005a703`, which is the whole point of the C-extension flip.
#   MEASURED across 8 of 8 fresh COSIM_BOOT=1 traces (rom.rcf md5
#   cab1bbe82d67d959d514dda9e338e3f9, 2048 words), every one carrying
#   `# XBITS 00 00000821 data 00000002 000000b1`.
#   PC RE-PINNED 0x0000005c -> 0x0000005a (2026-09-05, F11). The boot ROM was
#   re-cut for the bounded flash polls + WDT arm (rom.rcf md5
#   99b0c95dfb3fc0da52a49d1a68efa904, .text 7,376 -> 7,532 B), which moved this
#   `lw` two bytes earlier. The read is unchanged: still GPIO0 P0IN at 0x4000,
#   still `lw a4,0(a1)` (16-bit `4198`), and the very next instruction is still
#   `and a4,a4,128` (bin/flashboot.dump, check_boot_mode / check_boot_mode+0x2).
#   MEASURED, not inferred: 8 of 8 COSIM_BOOT=1 traces at RUN_KEY=f11_boot8
#   (COSIM_RCF_LINK=kf8) applied this entry exactly once each, and mk_inject did
#   NOT refuse BOOT_ALLOW_X_1='*:00004000:000000b1', i.e. the LFXT phase bit 4
#   did not flip this time.
#   HELD at 0x0000005a through the 2026-09-13 ROM re-cut (rom.rcf md5
#   cea7e60f4723f63acfd92c5883716f1e): that cut moved the data map, first
#   changed word at 0x39a, so every instruction below it kept its address.
#   RE-MEASURED (W8), not assumed: 8 of 8 COSIM_BOOT=1 traces at
#   RUN_KEY=w8_boot8b, COSIM_RCF_LINK=w80, applied this entry exactly once
#   each; the kept trace (RUN_KEY=w8_keep1) carries `R 00 0000005a 4198 0e
#   000000bx` and `# XBITS 00 00000a1f data 00000002 000000b1`, so
#   BOOT_ALLOW_X_1='*:00004000:000000b1' still contradicts no driven bit.
0000005a 00004000
#
# ENTRY 2 — SPI0 RX buffer read before any transfer has completed
#   pc   0x00000198  `lw x5, 12(x10)`   (encoding 00c52283)
#   addr 0x0000420c  SPI0 RXBUF
#   Observed:  rdval / L-data = 000000xx   (whole low byte undriven)
#   Rationale: the first read drains a shift register that has never been
#   loaded; the boot's flash-copy loop discards this first word. v1_report.md
#   §8.2, same classification. Verified stable across two runs.
#   PC RE-PINNED 0x00000198 -> 0x0000015c (2026-08-23), same cause as entry 1.
#   This one did NOT re-encode: the trace still reads `00c52283`, the exact
#   `lw x5,12(x10)` named above, at the same 0x420c and with the same
#   000000xx. Only its address in the ROM moved.
#   MEASURED across the same 8 of 8 traces:
#   `# XBITS 00 0000084f data 000000ff 00000000`.
#   PC RE-PINNED 0x0000015c -> 0x000001b6 (2026-09-05, F11), same cause. Still
#   the 32-bit `00c52283` `lw t0,12(a0)` at 0x420c (bin/flashboot.dump,
#   spi0_tx_complete_done); the bounded-poll rewrite added the two
#   spi0_poll_* loops ahead of it. Applied once in each of the same 8 traces.
#   HELD at 0x000001b6 through the 2026-09-13 ROM re-cut, same cause as entry
#   1. RE-MEASURED (W8): applied once in each of the same 8 traces; the kept
#   trace carries `R 00 000001b6 00c52283 05 000000xx` and
#   `# XBITS 00 00000a5a data 000000ff 00000000`. Only the FIRST read is
#   x-tainted: every later `lw t0,12(a0)` at this pc reads a defined word.
000001b6 0000420c

# A10 CORRECTION (2026-07-31, W5). Entry 1's substituted value above read
# ':000000b0' until now -- the V3 value, kept here after amendment A10 had
# already corrected it in xrun_cosim.sh (BOOT_ALLOW_X_1). It was WRONG: the
# RTL DRIVES bit 0 of this read to 1 (`# XBITS ... data 00000002 000000b1`
# -- only bit 1 is undriven), so 0xb0 contradicted a driven bit and
# mk_inject now REFUSES it with EXIT_REFUSED(5). Measured at W5, not
# inferred. The lesson is the R-W2-3 one: this file is the allowlist's
# written RATIONALE, so a stale value here is worse than a stale value in a
# script -- the next reader trusts it. Canonical copy + drift checker:
# tools/cosim/gate/ and tools/cosim/check_gate_files.py.
# Injection and comparison must be kept consistent: the reference is handed a
# concrete value, and the comparator is told not to hold the RTL's undriven
# nibbles against it.
