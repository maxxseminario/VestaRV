# THIS ROW IS EXPECTED TO DIVERGE, AND THAT IS ITS PASS CONDITION.  The K0

#     mismatch at the `csrw mhpmevent3` -- the standing D-2026-07-29-1;
#   * with ZIHPM ON the mechanism INVERTS and gets worse: the RTL stores the
#     full 32 bits and logs `C 323 00000001` where the reference WARLs to zero

#   * `hpm-warl` reconciles BOTH of those -- and deliberately NOT the counter
#     VALUES, because the RTL has real event counters (arbiter stall, grant,
#     sleep, trap entry) and the reference hardwires them to zero.
# So the row runs until `extzihpm.S:79`'s `csrr s2, mhpmcounter3` and diverges
# there.  **That divergence is F1 -- the hpm counter values under the gated
# clock -- becoming measurable for the FIRST time**, which the disposition
# records as masked in every other configuration.  It is REPORT-NOT-FIX (K5).

# Note when reading it: `extzihpm`'s ON-arm assertions are TIMING-derived
# (`:89` requires stalls > grants, `:98` requires strict growth), so the counter
# values it reads are not reproducible by ANY reference model.  This is not a
# gap in the amendment; it is what a hardware event counter IS.
