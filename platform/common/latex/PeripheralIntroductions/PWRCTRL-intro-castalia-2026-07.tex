\section{Overview}

The power controller (\peripheral{PWRCTRL}) switches the power domains of the channel tiles, harts 1 to \MaxHartIndex{}, and in configurations wired for field power it also owns the boot gate that holds every hart in reset until the harvested supply is good. The power domains themselves, and what cold gating means for software, are described in the Reset, clocks and power chapter (Section \ref{s:powerdomains}).

\begin{itemize}
	\item One gate bit per channel tile in \register{PWRCR} (mask \texttt{\PwrGateMask}); hart 0 has no gate bit
	\item A per-tile hardware sequencer that orders isolation, reset and the header switches in both directions
	\item Read-only sequencer state per tile in \register{PWRSR}, one nibble per hart
	\item Cold gating: a gated tile loses all state and cold-boots through the shared ROM on wake
	\item Boot gate configuration in \register{PWRWAKE} and live status in \register{PWRSTS}
	\item All domains power up on at reset; the controller is inert until written
\end{itemize}

\section{Functional description}

\subsection{Gate sequencer}

Setting bit $h$ of \register{PWRCR} starts tile $h$'s power-down sequence: the isolation clamps assert on the always-on side of the boundary, the tile is held in reset, and only then do the header switches open, so that no floating signal ever reaches the shared fabric. Clearing the bit runs the sequence in the other order, with a rail-settle delay sized for the tile's header-switch chain before the reset is released. The sequencer never aborts a transition: a gate-bit change made mid-sequence takes effect when the current sequence completes. Bit 0 (\bitfield{PWRH0}) is reserved, reads 0 and ignores writes, because hart 0 is always on; a write of \texttt{\PwrGateMask} therefore gates every channel tile and leaves hart 0 running. The write is qualified by byte lane 0 only, so full-word stores are used.

\register{PWRSR} reports the sequencer state of each tile as a 4-bit code in nibble $h$ (\bitfield{PWRST0} to \bitfield{PWRST4}); 0 is on and 3 is off, with the intermediate codes marking the sequence in progress. Software polls the nibble after a write to \register{PWRCR}, because the transition takes several cycles and the tile must not be relaunched before its nibble reads 0.

\subsection{Boot gate}

The boot gate is a hold-in-reset combined into every hart's outer reset. All of its state lives on the always-on MCLK domain and evaluates once per cycle. The three pad-side inputs (\texttt{PGOOD}, the strap and the NFC field-detect level) are double-flop synchronized, so they reach the gate two MCLK cycles late.

The strap is sampled once: a counter starts at reset release and, eight MCLK cycles later, latches the synchronized strap level into \bitfield{PWSTRAP} and sets \bitfield{PWSTRAPVLD}. A strapped board thereby arms the gate, adds \texttt{PGOOD} as a release condition and enables re-hold with no software. The gate is released during that sampling window so that a normal board's boot is never delayed; a strapped board's harts may therefore begin a first fetch and then be re-held, which is harmless because the hold is the same outer reset that cleared them at power-on and the eventual release runs a clean cold boot.

The effective policy combines the strap defaults with the \register{PWRWAKE} overrides:
\begin{itemize}
	\item armed = \bitfield{PWGATEEN} or strapped
	\item release on \texttt{PGOOD} = \bitfield{PWRLSPGOOD} or strapped
	\item release on field detect = \bitfield{PWRLSFIELD}
	\item re-hold = \bitfield{PWREHOLD} or strapped
	\item release = \bitfield{PWSWRLS}, or (\texttt{PGOOD} live and release on \texttt{PGOOD}), or (field live and release on field detect)
	\item hold = armed and not (release, when re-hold is set; the sticky latch of every past release, when it is clear)
\end{itemize}
The gate output is registered, so releases and re-holds are glitch-free and take effect one cycle after their condition resolves. With re-hold set the hold tracks the release condition: a \texttt{PGOOD} drop re-asserts the hold on the next cycle and the harts re-enter reset at once, because without retention there is nothing a grace period could save. With re-hold clear the first release is final until the next chip reset, for systems in which supervising software owns brownout policy. An armed gate with no release source holds until \bitfield{PWSWRLS}, which production test uses to prove the gate is load-bearing.

\register{PWRSTS} reports the synchronized live levels (\bitfield{PWPGOODLIV}, \bitfield{PWFIELDLIV}), the sampled strap (\bitfield{PWSTRAP}, \bitfield{PWSTRAPVLD}), the gate state (\bitfield{PWBOOTHOLD}) and the release latch (\bitfield{PWRRLSLATCH}). Software can only observe the gate released or arm it for the next hold, because while the hold is active nothing executes.

\section{Interrupts and events}

Not applicable. The controller raises no vector; the NFC field-detect level used as a release source is available separately as \peripheral{NFCx} vector 94, and tile state is polled in \register{PWRSR}.

\section{Programming}

\subsection{Gating tile $h$}

\begin{enumerate}
	\item Confirm the tile is parked in its boot-ROM sleep or has finished its work, and that any data it must keep is in shared RAM.
	\item Set bit $h$ of \register{PWRCR}.\bitfield{PWRGATE} with a full-word store.
	\item Poll nibble $h$ of \register{PWRSR} until it reads 3.
\end{enumerate}

\subsection{Waking tile $h$}

\begin{enumerate}
	\item Clear bit $h$ of \register{PWRCR}.\bitfield{PWRGATE} with a full-word store.
	\item Poll nibble $h$ of \register{PWRSR} until it reads 0.
	\item Write the tile's loader mailbox row and send it a software interrupt (Section \ref{ss:multicore-boot}).
\end{enumerate}

\subsection{Arming the boot gate from software}

\begin{enumerate}
	\item Set \register{PWRWAKE}.\bitfield{PWRLSPGOOD}, and \register{PWRWAKE}.\bitfield{PWRLSFIELD} if the RF field is also a release source.
	\item Set \register{PWRWAKE}.\bitfield{PWREHOLD} if the hold is to track \texttt{PGOOD}.
	\item Set \register{PWRWAKE}.\bitfield{PWGATEEN}.
\end{enumerate}

A harvested board needs none of this: with the strap high and the supervisor's output on \texttt{PGOOD}, the hardware defaults arm the gate, wait on \texttt{PGOOD} and re-hold on brownout, so the first instruction any hart executes runs after the supply is declared good.

\subsection{Supercap duty-cycled service loop}

\begin{enumerate}
	\item Gate the unused tiles through \register{PWRCR}.
	\item Route \peripheral{NFCx} vector 94 to the serving hart in its \peripheral{IRQROUTER} row.
	\item Provision and arm the NFC block in listen mode with auto-read.
	\item Gate unused memories and banks in \register{BLOCKPWR} and divide MCLK in \register{CLKDIVCR}.
	\item Execute \asminline{sleep}; a reader's field raises the interrupt and the hart resumes with its state intact.
\end{enumerate}

\section{Usage notes}

\paragraph{Gate only parked or quiesced tiles.} Gating is cold; a tile gated mid-transaction loses its work and any shared-bus transaction it had in flight is answered by the clamps.

\paragraph{Use full-word stores to \register{PWRCR}.} The write is qualified by byte lane 0 only.

\paragraph{Poll \register{PWRSR} rather than adding delays.} The sequencer includes the rail-settle delay; the nibble reads 0 when the tile can be relaunched.

\paragraph{Check \register{PWRSR} before trusting an aperture read.} A gated tile's TCM aperture returns zeros, and zero is a legal TCM value.

\paragraph{Keep the boot gate disarmed on a normally powered board.} An armed gate with no release source holds every hart, hart 0 included, until \bitfield{PWSWRLS} is written, which nothing can do while the hold is active.
