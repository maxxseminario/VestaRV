\chapter{Debug} \label{s:debug}

\section{Overview}

Hardware debug reaches into the chip over dedicated wires that depend on no software: it stops a hart between instructions, reads and writes its registers and memory, and starts it again. It works on a hart stuck in a loop, on a hart that has taken an illegal instruction and stopped retiring, and, with halt-on-reset armed, on a hart before its first instruction. The Forth monitor over \peripheral{UART0} (Section \ref{s:forth}) is the cooperative alternative and needs the chip to be executing correctly enough to answer.

\begin{itemize}
	\item IEEE 1149.1 JTAG transport on five pins, with a 5-bit instruction register and a 41-bit DMI data register
	\item One Debug Module for the whole chip, reaching every hart, implementing RISC-V debug specification 1.0 (\bitfield{version} = 3)
	\item Halt, resume, halt-on-reset and single-step per hart; halt groups across harts
	\item Abstract access-register commands with one data word and a two-word program buffer plus an implicit third word
	\item Debug mode in the hart with four CSRs (\register{dcsr}, \register{dpc}, \register{dscratch0}, \register{dscratch1}) and the \asminline{DRET} instruction
	\item Memory access through the halted hart's own load and store instructions; no system bus access, no hardware triggers
\end{itemize}

This configuration includes the debug system; the sections below document it.
\else
\textbf{This configuration does not include the debug system.} The four Debug-Mode control registers \register{dcsr}, \register{dpc}, \register{dscratch0} and \register{dscratch1} (\texttt{0x7B0} to \texttt{0x7B3}) are not implemented: any CSR instruction naming an address in \texttt{0x7B0} to \texttt{0x7BF} is an illegal instruction from any privilege level, and the \asminline{DRET} instruction (\texttt{0x7B200073}) is an illegal instruction. There is no JTAG port, no Debug Transport Module and no Debug Module, and no external agent can halt, inspect or resume a hart. \section{Functional description}

\subsection{JTAG} \label{ss:debug-jtag}

JTAG is the IEEE 1149.1 serial protocol: four mandatory wires and an optional fifth, driving a sixteen-state Test Access Port (TAP) whose only input is \pin{TMS}.

\begin{center}
\begin{tabular}{ l l p{9.2cm} }
	\textbf{Wire} & \textbf{Direction} & \textbf{Purpose} \\ \hline
	\pin{TCK} & in & Test clock, supplied by the probe. Everything on the port is synchronous to it; it has no relationship to any clock inside the chip. \\
	\rowcolor{tablehighlightcolor} \pin{TMS} & in & Test mode select, sampled on every rising \pin{TCK} edge; this one wire drives the state machine. \\
	\pin{TDI} & in & Serial input to the selected shift register. \\
	\rowcolor{tablehighlightcolor} \pin{TDO} & out & Serial output of that register. \\
	\pin{TRSTn} & in & Optional asynchronous reset of the port; present on this chip. \\ \hline
\end{tabular}
\end{center}

The states form two lobes, one for scanning an instruction and one for scanning data, joined at a common idle state. Test-Logic-Reset is the reset state, and holding \pin{TMS} high for five \pin{TCK} clocks reaches it from any state, which is the standard's guaranteed recovery for a probe that has lost track of the machine. The IR lobe (Select-IR, Capture-IR, Shift-IR, Exit1-IR, Pause-IR, Exit2-IR, Update-IR) loads the instruction register; the DR lobe loads whichever data register the current instruction selects. Figure \ref{fig:tap-state-graph} is the machine with every transition this chip implements.

A scan has three phases: Capture loads the selected register in parallel from what it shadows, Shift moves one bit in from \pin{TDI} and one out on \pin{TDO} per \pin{TCK} (least-significant bit first), and Update commits the shifted-in value. One scan therefore reads the old contents and writes the new ones at once, so a debugger's traffic is a stream of fixed-length shifts rather than read-then-write pairs. Figure \ref{fig:jtag-scan} follows one four-bit scan.

The port is passive with respect to the chip's own clocks: it answers while the harts run, while they are halted, and while they are held in reset. Because the standard's BYPASS instruction selects a single flip-flop, several devices can be chained (\pin{TDO} of one to \pin{TDI} of the next) and a debugger addresses one while the others contribute one bit of padding each.

\subsection{The RISC-V debug stack} \label{ss:debug-stack}

The RISC-V debug specification defines the meaning of the scanned bits in four layers, each independent of the internals of the one below it, so that one debugger drives different chips.

\begin{center}
\begin{tabular}{ l p{11.0cm} }
	\textbf{Layer} & \textbf{What it is} \\ \hline
	\textbf{DTM} & The Debug Transport Module: the TAP plus the logic that turns one DR scan into one transaction on the interface below. It has no knowledge of harts. \\
	\rowcolor{tablehighlightcolor} \textbf{DMI} & The Debug Module Interface: a 7-bit address, 32-bit data bus with three operations (no-op, read, write). Anything that drives a DMI can debug the chip; JTAG is the transport this chip provides. \\
	\textbf{DM} & The Debug Module: registers on the DMI implementing run control (select a hart, halt it, query its state, run a short program on it, resume it). One DM serves every hart. \\
	\rowcolor{tablehighlightcolor} \textbf{Debug mode} & A state of the hart, effectively a privilege level above machine mode, in which the hart executes the debugger's code and has control registers that exist only there. \\ \hline
\end{tabular}
\end{center}

A halted hart is not a frozen hart. Halting does not stop the clock; it diverts the hart, between instructions, to a fixed address where the debugger's code waits, and the hart executes there until told what to do. To read a register the debugger writes a two- or three-instruction program into memory, has the hart run it, and reads back where the program put the answer. Every property that follows derives from this: the debugger needs memory for its code, a register read can report an exception, the hart's \asminline{s0} and \asminline{s1} must be saved before anything else, and memory accesses on the debugger's behalf go through the ordinary bus with ordinary arbitration.

\subsection{Debug port} \label{ss:debug-port}

The debug port occupies five pins, present only on the LQFP-100 package; a smaller package has the debug system in silicon with nowhere to bond it. The pins are ordinary 3.3 V digital I/O on the \texttt{VDDPST}/\texttt{VSSPST} domain, may be left unconnected, and are placed on the south and east edges away from the analog band.

\begin{center}
\begin{tabular}{ l l l p{6.6cm} }
	\textbf{Pin} & \textbf{Signal} & \textbf{I/O} & \textbf{Idle state when unconnected} \\ \hline
	47 & \pin{TCK} & Input & Pulled low. \\
	\rowcolor{tablehighlightcolor} 48 & \pin{TMS} & Input & Pulled high, as IEEE 1149.1 requires, so that five clocks from a disconnected probe still reach Test-Logic-Reset. \\
	49 & \pin{TDI} & Input & Pulled high. \\
	\rowcolor{tablehighlightcolor} 50 & \pin{TDO} & Output & Driven; held quiet between shift states so the pin is well behaved in a chain. \\
	51 & \pin{TRSTn} & Input & Pulled low; see below. \\ \hline
\end{tabular}
\end{center}

The pull on \pin{TRSTn} is a deliberate deviation from IEEE 1149.1, which wants the pin to idle high so that a port with a floating reset is available to a probe. This chip pulls it low, holding the TAP in reset, because the transport is optional: a board that does not use it leaves all five pins unconnected, and the desired behaviour is then a port that is inert rather than one that is attachable by anyone who touches the pins. A board that uses the port drives \pin{TRSTn} high.

A DR scan of IDCODE returns \texttt{0x1CA57EEF}: version \texttt{1}, part number \texttt{0xCA57}, manufacturer \texttt{0x777}, mandatory LSB \texttt{1}. The manufacturer field is not a valid JEDEC JEP106 code and is not registered to anyone; the value is deliberately invalid rather than borrowed, so discovery software identifies the part by its full IDCODE.

\subsection{Debug Transport Module} \label{ss:debug-dtm}

The DTM implements the TAP and four data registers. The instruction register is five bits wide and resets to IDCODE (Table \ref{t:debug-ir}).

\begin{table}[htb]
	\centering
	\caption{Debug Transport Module instruction register values.}
	\label{t:debug-ir}
	\begin{tabular}{ l l l p{6.4cm} }
	\textbf{IR value} & \textbf{Instruction} & \textbf{DR width} & \textbf{Selects} \\ \hline
	\texttt{0x01} & IDCODE & 32 & The identification value. The reset instruction, so the first DR scan after a port reset returns the IDCODE. \\
	\rowcolor{tablehighlightcolor} \texttt{0x10} & DTMCS & 32 & The transport's control and status register. \\
	\texttt{0x11} & DMI & 41 & One transaction on the Debug Module Interface. \\
	\rowcolor{tablehighlightcolor} \texttt{0x1F} & BYPASS & 1 & A single flip-flop, for a multi-device chain. \\
	\textit{any other} & BYPASS & 1 & Every unrecognised instruction selects the one-bit chain, so the selected length never depends on what was scanned before. \\
	\hline
	\end{tabular}
\end{table}

Test-Logic-Reset sets the instruction register to IDCODE and nothing else: it does not clear the sticky status below and does not discard a waiting result, so a debugger that has recovered a lost TAP still clears the status with \bitfield{dmireset}. \pin{TRSTn} resets the entire transport.

DTMCS reports the transport's capabilities and carries the two recovery strobes:

\begin{center}
\begin{tabular}{ l l p{8.6cm} }
	\textbf{Bits} & \textbf{Field} & \textbf{Meaning} \\ \hline
	\texttt{[3:0]} & \bitfield{version} & \texttt{1}: satisfies the 0.13 and 1.0 debug specifications. \\
	\rowcolor{tablehighlightcolor} \texttt{[9:4]} & \bitfield{abits} & \texttt{7}: the DMI address is seven bits, so the DMI register is $7 + 32 + 2 = 41$ bits. \\
	\texttt{[11:10]} & \bitfield{dmistat} & Sticky transaction status. \\
	\rowcolor{tablehighlightcolor} \texttt{[14:12]} & \bitfield{idle} & \texttt{7}: Run-Test/Idle clocks to insert between a DMI scan and the scan that collects its result. \\
	\texttt{[16]} & \bitfield{dmireset} & Write \texttt{1} to clear \bitfield{dmistat} and abandon any outstanding transaction. Reads \texttt{0}. \\
	\rowcolor{tablehighlightcolor} \texttt{[17]} & \bitfield{dmihardreset} & Write \texttt{1} to do the above and clear the stored result. Reads \texttt{0}. \\ \hline
\end{tabular}
\end{center}

The \bitfield{idle} value is derived from the real latency of the slowest transaction class. A DMI access to one of the Debug Module's own registers completes in eight to ten cycles of the main clock; an access to \register{data0} or a program-buffer word is proxied into shared memory through the arbiter and takes tens of cycles. Against a \pin{TCK} period of at least 140 ns (7.14 MHz or below) and a 24 MHz main clock, the worst class needs six idle cycles and \texttt{7} gives one cycle of margin. It is a recommendation, not a guarantee: at a faster \pin{TCK}, or while the harts contend for the shared bus, a transaction can still be outstanding when the debugger returns, which is reported as busy and answered by clearing the status and reissuing.

The DMI data register is 41 bits (Figure \ref{fig:dmi-field}): \bitfield{op} \texttt{[1:0]}, \bitfield{data} \texttt{[33:2]}, \bitfield{address} \texttt{[40:34]}. On the way in, \bitfield{op} is \texttt{00} for no operation, \texttt{01} for read and \texttt{10} for write; on the way out it is \texttt{00} for success, \texttt{10} for failed and \texttt{11} for busy. A no-operation scan starts nothing, which makes a capture-only scan (zeros shifted in to read the previous result) safe.

	\caption{Field layout of the 41-bit DMI data register.}
	\label{fig:dmi-field}

\bitfield{dmistat} is sticky with two values: \texttt{3} (busy) if a scan is captured while a transaction is in flight or a new transaction is scanned in while one is outstanding, and \texttt{2} (failed) if a transaction fails, for instance on a DMI address the Debug Module does not implement. While \bitfield{dmistat} is nonzero, further DMI scans are dropped, so that a debugger cannot issue a long sequence of writes after the first one failed. The status is cleared by \bitfield{dmireset} or \bitfield{dmihardreset} and by nothing else; neither Test-Logic-Reset nor a system reset clears it. \subsection{Debug Module} \label{ss:debug-dm}

There is one Debug Module for the chip. It runs on the always-running main clock, is reached by the DTM through the DMI, and, because it must place instructions where a hart will fetch them, it is also a master on the shared-memory arbiter alongside the harts (Section \ref{s:multicore}). Table \ref{t:debug-dmi} is its DMI address map.

\begin{center}
\begin{longtable}[c]{ l l p{9.0cm} }
\caption{Debug Module registers at their DMI addresses.} \label{t:debug-dmi} \\
\hline \textbf{DMI} & \textbf{Register} & \textbf{Purpose} \\ \hline \endfirsthead
\multicolumn{3}{c}{\textit{\tablename\ \thetable\ continued from previous page}} \\ \hline
\textbf{DMI} & \textbf{Register} & \textbf{Purpose} \\ \hline \endhead
\hline \multicolumn{3}{c}{\textit{\tablename\ \thetable\ continued on next page}} \\ \endfoot \hline \endlastfoot
\texttt{0x04} & \register{data0} & The abstract-command data word, backed by shared memory. \\
\rowcolor{tablehighlightcolor} \texttt{0x10} & \register{dmcontrol} & Run control: enable the module, select a hart, halt it, resume it. \\
\texttt{0x11} & \register{dmstatus} & The selected hart's state and the module's capabilities. Read-only. \\
\rowcolor{tablehighlightcolor} \texttt{0x12} & \register{hartinfo} & Reads zero: no scratch registers and no debugger-visible \register{data0} address. Read-only. \\
\texttt{0x13} & \register{haltsum1} & Reads zero. Present because debuggers probe it during discovery. \\
\rowcolor{tablehighlightcolor} \texttt{0x16} & \register{abstractcs} & Abstract-command status: busy, error code, sizes. \\
\texttt{0x17} & \register{command} & Write to start an abstract command. Reads zero. \\

\rowcolor{tablehighlightcolor} \texttt{0x21} & \register{progbuf1} & Program-buffer word 1, backed by shared memory. \\
\texttt{0x32} & \register{dmcs2} & Halt-group membership of the selected hart. \\
\rowcolor{tablehighlightcolor} \texttt{0x40} & \register{haltsum0} & One bit per hart: halted and reachable. The only status register that ignores the hart selection. \\
\hline
\end{longtable}
\end{center}

Any other DMI address returns failed, which because \bitfield{dmistat} is sticky also stalls the transport until cleared. \register{haltsum1} and \register{abstractauto} answer with a successful zero because debuggers routinely read them during discovery. \register{hartinfo} reads zero on purpose: with \texttt{dataaccess} = 0 a conforming debugger does not consult \texttt{dataaddr} and reaches memory through the program buffer, which is the only path this chip supports, and the real \register{data0} address does not fit the twelve-bit field.

\register{dmcontrol} is where every session starts. \bitfield{dmactive} (bit 0) must be written 1 before the module does anything; writing 0 resets the module's own state but not the harts. \bitfield{hartsel} (bits \texttt{[25:16]}) selects the hart the status and command registers refer to; all ten bits are implemented, and an index that does not exist is reported as nonexistent rather than clamped, which is what makes hart-count discovery work. \bitfield{haltreq} (bit 31) is a level that asks the selected hart to halt while set. \bitfield{resumereq} (bit 30) is a write-one request that is queued rather than refused and ignored for a hart that is not halted or not reachable. \bitfield{setresethaltreq} and \bitfield{clrresethaltreq} (bits 3 and 2) arm and disarm halt-on-reset for the selected hart. \bitfield{ndmreset}, \bitfield{hartreset} and \bitfield{hasel} are not implemented; they read zero and ignore writes.

\register{dmstatus} reports \bitfield{version} = 3 (specification 1.0), \bitfield{authenticated} = 1 (no authentication), \bitfield{hasresethaltreq} = 1 and \bitfield{impebreak} = 1. Hart state is reported through six pairs of bits, and because one hart is selected at a time both bits of each pair carry the same value:
\begin{itemize}
	\item \bitfield{allhalted}, \bitfield{anyhalted}
	\item \bitfield{allrunning}, \bitfield{anyrunning}
	\item \bitfield{allunavail}, \bitfield{anyunavail}
	\item \bitfield{allnonexistent}, \bitfield{anynonexistent}
	\item \bitfield{allresumeack}, \bitfield{anyresumeack}
	\item \bitfield{allhavereset}, \bitfield{anyhavereset}
\end{itemize}

\register{abstractcs} reports \bitfield{progbufsize} = 2 and \bitfield{datacount} = 1. \bitfield{busy} (bit 12) is set while a command runs, and the module stays readable so the debugger can poll. \bitfield{cmderr} (bits \texttt{[10:8]}) is write-one-to-clear:

\begin{center}
\begin{tabular}{ l l p{9.2cm} }
	\textbf{\bitfield{cmderr}} & \textbf{Meaning} & \textbf{Raised when} \\ \hline
	\texttt{0} & none & No error. \\
	\rowcolor{tablehighlightcolor} \texttt{1} & busy & A command was written while one was running, or \register{data0} or a program-buffer word was accessed while the bus engine was busy. \\
	\texttt{2} & not supported & The command type is not access-register, or the transfer size is not 32-bit. \\
	\rowcolor{tablehighlightcolor} \texttt{3} & exception & The hart took an exception while executing the command. \\
	\texttt{4} & halt/resume & The selected hart was not halted when the command was written. \\
	\rowcolor{tablehighlightcolor} \texttt{7} & other & The command did not complete within the module's internal timeout. \\ \hline
\end{tabular}
\end{center}

A command written while \bitfield{cmderr} is nonzero is ignored entirely: it does not run and does not clear the error.

\register{command} implements one command type, access register: it transfers one 32-bit value between \register{data0} and a register of the halted hart, optionally executing the program buffer afterwards. The fields are \bitfield{aarsize} (\texttt{[22:20]}, which must be 2), \bitfield{postexec} (bit 18), \bitfield{transfer} (bit 17), \bitfield{write} (bit 16) and \bitfield{regno} (\texttt{[15:0]}). Register numbers \texttt{0x1000} to \texttt{0x101F} are \asminline{x0} to \asminline{x31}; any other number is a CSR address. Access memory is not implemented and returns not supported; memory is reached by executing \asminline{lw} or \asminline{sw} from the program buffer.

\register{data0} and the program-buffer words are shared memory, not flip-flops: a DMI access to \texttt{0x04}, \texttt{0x20} or \texttt{0x21} becomes a read or write of a word in shared memory issued by the Debug Module through the arbiter. That is why those addresses are the slow class behind \bitfield{idle} = 7, and why an access to them while the bus engine is busy answers with zero data and sets \bitfield{cmderr} to busy. The program buffer is two DMI-visible words plus an implicit third word supplied by hardware, which is why \bitfield{impebreak} reads 1.

\subsection{Debug mode in the hart} \label{ss:debug-hart}

A hart enters debug mode for one of four reasons, recorded in \register{dcsr}.\bitfield{cause}:

\begin{center}
\begin{tabular}{ l l p{9.0cm} }
	\textbf{\bitfield{cause}} & \textbf{Reason} & \textbf{Notes} \\ \hline
	\texttt{1} & \asminline{EBREAK} & A software breakpoint, taken only when \register{dcsr}.\bitfield{ebreakm} is set (or when the hart is already in debug mode). \\
	\rowcolor{tablehighlightcolor} \texttt{3} & Halt request & The Debug Module asserted \bitfield{haltreq}. \\
	\texttt{4} & Single step & The one instruction permitted by \register{dcsr}.\bitfield{step} has retired. \\
	\rowcolor{tablehighlightcolor} \texttt{5} & Halt on reset & \bitfield{setresethaltreq} was armed when this hart left reset. \\ \hline
\end{tabular}
\end{center}

On entry the hart saves its program counter to \register{dpc}, records the cause and previous privilege level in \register{dcsr}, sets debug mode, and jumps to the fixed address \texttt{0x00010780} in the shared window. Four CSRs exist only in debug mode:

\begin{center}
\begin{tabular}{ l l p{9.2cm} }
	\textbf{Address} & \textbf{Register} & \textbf{Contents} \\ \hline
	\texttt{0x7B0} & \register{dcsr} & \bitfield{xdebugver} \texttt{[31:28]} reads 4; \bitfield{ebreakm} (15) makes \asminline{EBREAK} enter debug mode; \bitfield{ebreaku} (12) does the same for user mode where it is configured; \bitfield{cause} \texttt{[8:6]} is read-only; \bitfield{step} (2) enables single-stepping; \bitfield{prv} \texttt{[1:0]} is the privilege level to return to. \\
	\rowcolor{tablehighlightcolor} \texttt{0x7B1} & \register{dpc} & The saved program counter. Bit 0 is hardwired zero; bit 1 is writable only where the compressed extension is configured. \\
	\texttt{0x7B2} & \register{dscratch0} & Scratch word for the debugger. \\
	\rowcolor{tablehighlightcolor} \texttt{0x7B3} & \register{dscratch1} & Second scratch word. \\ \hline
\end{tabular}
\end{center}

Every CSR instruction naming an address in \texttt{0x7B0} to \texttt{0x7BF} is an illegal instruction outside debug mode, so a program cannot read the debugger's saved state or forge an entry. \asminline{DRET} (\texttt{0x7B200073}) leaves debug mode, restoring the program counter from \register{dpc} and the privilege level from \register{dcsr}.\bitfield{prv}; outside debug mode it is an illegal instruction.

Five behaviours decide whether a session works:

\begin{itemize}
	\item \textbf{The halt request is unmaskable.} It is recognised at the thirteen sequencer points at which an interrupt is recognised plus the terminal trap state, so a hart that has taken an illegal instruction and stopped retiring (Section \ref{ss:priv-legacy}) can be halted and inspected. Neither \register{mstatus}.\bitfield{MIE} nor \register{mtrapctl}.\bitfield{LEGACY} affects it.
	\item \textbf{An \asminline{EBREAK} records its own address in \register{dpc}}, not the address after it, so a debugger resuming past a software breakpoint adds the instruction's length itself. Every other cause is taken between instructions and \register{dpc} is the resume address.
	\item \textbf{No interrupt is taken in debug mode.} Sources stay pending as levels and are delivered after \asminline{DRET}, so a session neither loses interrupts nor runs the application's handlers underneath the debugger.
	\item \textbf{An exception in debug mode re-enters debug mode} at the same fixed address, leaving \register{dpc}, \register{dcsr}, \register{mepc}, \register{mcause} and \register{mtval} untouched, which is what makes a faulting abstract command report \bitfield{cmderr} = 3 instead of ending the session.
	\item \textbf{Halt-on-reset is sampled once, at reset release.} Arming \bitfield{setresethaltreq} affects the next time the hart leaves reset and does not halt a running hart.
\end{itemize}

Single-step diverts at the stepped instruction's own dispatch, so exactly one instruction retires per step; stepping is inactive inside debug mode. Figure \ref{fig:debug-mode-state} collects the two states.

\subsection{Halt groups and unavailable harts} \label{ss:debug-groups}

\register{dmcs2} assigns the selected hart to one of eight halt groups; group 0, the reset value, is no group. When any member of a group halts for any reason, including its own \asminline{EBREAK}, the Debug Module requests a halt of every other member, so a breakpoint in one hart stops the cooperating set at very nearly the same instant. Halting is grouped; resuming is done per hart.

Unavailable is a third state, distinct from halted. A hart whose power domain is off cannot answer the Debug Module, and the signals that would report its state are clamped to zero at the domain boundary; a clamped not-halted is indistinguishable from running, so the module takes a separate unavailable signal from the power controller and consults it before halted or running. The reported state resolves in the order nonexistent, unavailable, halted, running, and a gated hart reports \bitfield{allunavail}/\bitfield{anyunavail} with both halted and running clear. A halt request to a gated hart does nothing; the debugger powers the hart up through \peripheral{PWRCTRL} first, and because a hart returning from power-down cold-boots the ROM and parks, halt-on-reset is armed before powering it up to catch it on its first instruction.

The Debug Module writes the entry page itself, once when \bitfield{dmactive} is raised and again before acting on any hart it has just seen halt, so nothing is staged in advance and the page cannot be read-only memory. The page is assembled without compressed instructions, because execution of compressed or misaligned instructions from the shared window is outside the tested envelope (Section \ref{s:multicore}).

While a hart is halted, the single home of the interrupted program's \asminline{s0} and \asminline{s1} is the CSR pair \register{dscratch0} and \register{dscratch1}: a debugger that reads or writes \asminline{s0} reads or writes \register{dscratch0}, and a program-buffer change to \asminline{s0} survives to the next read because the exit sequence adopts the architectural pair into the CSRs first. The two words at \texttt{0x106F0} and \texttt{0x106F4} are the stub's own repair copies for a hart that re-enters debug mode from inside the page; the Debug Module writes them only when it authored a new value, and nothing else reads them. A plain halt and resume with no register writes leaves \asminline{s0} and \asminline{s1} as it found them.

\section{Interrupts and events}

Not applicable. The debug system raises no interrupt vector; a halted hart is observed through \register{dmstatus}, and interrupts pending on a hart in debug mode are delivered after \asminline{DRET}.

\section{Programming}

\subsection{Halt, read a register, resume} \label{ss:debug-worked}

The following session halts hart 2, reads its \asminline{a1} register and resumes it. Each step is one or more JTAG scans; a DMI read is two scans (one to issue the read and one, after the idle clocks, to collect the result), because the transport returns the previous transaction's result on every capture. Figure \ref{fig:debug-swimlane} draws the same steps across the four agents that perform them.

\begin{enumerate}
	\item Drive \pin{TRSTn} high, then clock \pin{TMS} high for five \pin{TCK} cycles. The instruction register is now IDCODE; a 32-bit DR scan returns \texttt{0x1CA57EEF}.
	\item Scan \texttt{0x10} (DTMCS) into the instruction register and read it: \bitfield{version} = 1, \bitfield{abits} = 7, \bitfield{idle} = 7. Insert seven Run-Test/Idle clocks after every DMI scan from here on.
	\item Scan \texttt{0x11} (DMI) into the instruction register. Every scan below is a 41-bit DR scan of \{\bitfield{address}, \bitfield{data}, \bitfield{op}\}.
	\item Write \texttt{0x00000001} to \register{dmcontrol} (\texttt{0x10}): \bitfield{dmactive}.
	\item Write \texttt{0x80020001} to \register{dmcontrol}: \bitfield{haltreq}, \bitfield{hartsel} = 2, \bitfield{dmactive}.
	\item Read \register{dmstatus} (\texttt{0x11}) until \bitfield{allhalted} (bit 9) is set. \bitfield{allunavail} means hart 2 is powered down; \bitfield{allnonexistent} means this configuration has fewer than three harts.
	\item Write \texttt{0x00020001} to \register{dmcontrol} to drop the halt request. The hart stays halted, because halting is a state of the hart, not a level the module holds.
	\item Write \texttt{0x00000700} to \register{abstractcs} (\texttt{0x16}) to clear any stale \bitfield{cmderr}.
	\item Write \texttt{0x0022100B} to \register{command} (\texttt{0x17}): \bitfield{aarsize} = 2, \bitfield{transfer}, \bitfield{regno} = \texttt{0x100B} (\asminline{x11}).
	\item Read \register{abstractcs} until \bitfield{busy} (bit 12) is clear, then check \bitfield{cmderr}.
	\item Read \register{data0} (\texttt{0x04}); this access is proxied through shared memory and is the one the seven idle clocks are sized for.
	\item Write \texttt{0x40020001} to \register{dmcontrol}: \bitfield{resumereq}, hart 2 selected. Read \register{dmstatus} until \bitfield{allresumeack} (bit 17) is set.
\end{enumerate}

To write a register, put the value in \register{data0} first and set \bitfield{write} (bit 16) in the command. To read or write memory, put an \asminline{lw} or \asminline{sw} in the program buffer, put the address in a register of the halted hart, and issue a command with \bitfield{postexec} set; the hart executes the instruction with its own privilege and its own view of the address space. If a scan returns \bitfield{op} = \texttt{10} or \texttt{11}, the transport has latched a sticky status and is dropping scans: read DTMCS, write \bitfield{dmireset}, and reissue.

\subsection{Connecting a debugger} \label{ss:debug-connect}

\section{Usage notes} \label{ss:debug-limits}

\paragraph{Clock the adapter at 3 MHz or below.} Every memory access and software breakpoint goes through the program buffer, whose bound is 3.60 MHz and shrinks under shared-bus contention; the 7.14 MHz port rating applies only to a master that honours \bitfield{idle}.

\paragraph{Do not infer a reset from \texttt{reset halt}.} The module has no system reset (\bitfield{ndmreset} is unimplemented), so the command halts every hart, re-reads the IDCODE and reports success while resetting nothing. For a genuine halt-on-reset, arm \bitfield{setresethaltreq} and power-cycle the hart's tile through \peripheral{PWRCTRL}.

\paragraph{Experiment on harts 1 to \MaxHartIndex{}, not hart 0.} The per-tile power controller is the lever behind every recovery procedure here; hart 0 has no gate bit, and the only thing that resets it is the \pin{resetn} pin, which also resets the Debug Module and ends the session.

\paragraph{Leave the program buffer through the exit sequence, not \asminline{EBREAK}.} A DMI write of exactly the 32-bit \asminline{EBREAK} encoding into \register{progbuf0} or \register{progbuf1} stores a jump to the common exit sequence instead, and reads back as that jump; only that encoding in those two registers is substituted. A program that genuinely traps is still reported as an exception.

\paragraph{Write memory one word at a time.} \register{abstractauto} is unimplemented, and a debugger that assumes it, as OpenOCD's burst-write path does, writes only the first word of a block and drops the rest; loading a program image over the debug port does not work.

\paragraph{Reach memory only through a halted, healthy hart.} There is no system bus access: memory is read and written by \asminline{lw} and \asminline{sw} executed from the program buffer, with the hart's own permissions and view of the address space, so a chip with no debuggable hart cannot have its memory inspected.

\paragraph{Use software breakpoints only.} There are no hardware triggers: no watchpoints and no fetch breakpoints. A breakpoint replaces the instruction with \asminline{EBREAK} under \register{dcsr}.\bitfield{ebreakm}, so breakpoints cannot be set in the boot ROM or any read-only region; data watchpoints by stepping are impractical.

\paragraph{Keep application software out of \texttt{0x10680} to \texttt{0x1087F}.} The region is ordinary shared RAM, so any master can overwrite it. Most damage repairs itself at the next halt, but a wrong first word at \texttt{0x10780} wedges the hart that halts into it: it takes an exception, re-enters at the same address, and is answered from the copy the tile already holds, so it never observes the repair. Recovery is a power cycle of that tile through \peripheral{PWRCTRL}.

\paragraph{Build with \texttt{priv.trapCsr} when enabling debug.} \texttt{debug.enable} requires the standard trap architecture (Section \ref{s:privarch}); the generator rejects the combination without it, because \asminline{EBREAK} is decoded on the standard privileged path.

\paragraph{Resume group members one at a time.} Halt groups stop a set together; resume groups are not implemented.

\paragraph{Expect specification behaviour, not simulator behaviour.} An unrecognised JTAG instruction selects BYPASS; \bitfield{dmistat} is driven and reports sticky failure as well as sticky busy; \bitfield{idle} reports the real requirement; an out-of-range \bitfield{hartsel} reports nonexistent; \register{dmstatus}.\bitfield{version} is 3. A debugger written against the specification finds the part conformant; one written against a particular simulator's quirks may not.

\paragraph{The debug port is not yet in a signed-off layout.} The five pins exist in the chip-level netlist and the LQFP-100 package definition; the current signed-off layout predates them.
