0.4 Global nets — the #1 silent-failure source

The AFE cells have no supply pins: supplies arrive on globals vdd!/vss!, and the folded-cascode bias arrives on globals bn! bnc! bp! bpc! driven by anatop_biasgen. In every testbench schematic you must place:
  • analogLib/vdc, vdc=vdd25, PLUS wired to a label vdd!, MINUS to gnd!
  • analogLib/gnd on gnd!, and a wire label tying vss! to gnd! (0 V)
  • For any DUT containing anatop_controlamp: either an anatop_biasgen instance (preferred, see TB-01 wiring) or four vdc sources onto labels bn! bnc! bp! bpc! using the values measured in TB-01.
Check the Maestro Global Signals panel after netlisting: every global listed there must have a source. An unfdriven global silently nets to 0 V and the amp "works" as a dead stick.

0.8 Driving the 6/16-bit config buses in testbenches

  • TCBias<5:0>, LCBias<5:0> (A2 trim, 2.5 V domain): tie bit<5> to vdd!, bits<4:0> to gnd! → mid-code 32. If a rev-1 register default differs, use that instead — note it in the maestro description field.
  • BiasAdj<5:0>: same mid-code 32 pattern.
  • tia_gain<15:0>: thermometer only. Bit i = 1 closes the T-gate shunting segment i. With G segments left un-shunted, Rf = G × 35 kΩ:
    Settingtia_gain<15:0>RfFS current
    Min gain1111 1111 1111 111035 k±33 µA
    Mid gain1111 1111 0000 0000280 k±4.1 µA
    Max gain0000 0000 0000 0000560 k±2.06 µA
    All-ones (0xFFFF) shunts every segment → Rf ≈ two T-gate on-resistances → TIA loop ~unity R feedback → likely instability and meaningless gain. Forbid it in firmware; never simulate it except deliberately in TB-04 test C.
  • En pins: tie to vdd! (2.5 V domain).

0.9 Maestro mechanics quick-reference

  1. Open TB schematic → Launch → ADE Assembler (or Explorer for a single test) → save the maestro view into the TB cell.
  2. Per test: Analyses as tabled below; Design Variables → Copy From Cellview, then set values from §0.5.
  3. Outputs → Setup… → add each expression string below verbatim (type: expression). Plots marked ⊞ should also be saved as signals.
  4. Data → Corners → add §0.3 set; enable per the test's "Corners" row.
  5. stb analyses need an analogLib/iprobe instance in the schematic at the marked spot; select it in the stb form ("Probe Instance"). If reported phase margin looks like 180° − expected, the probe is flipped — rotate it.
  6. Monte Carlo tests: Run Mode → Monte Carlo Sampling, mismatch only, 200 points, "All" for save-allowed outputs.

0.10 Temperature sweeps — exact steps (and why bg_temp throws eval errors)

A tempco needs a swept dc analysis, not a parametric run: the ymax()/ymin() expressions in TB-01 operate on a waveform whose x-axis is temperature. Set the sweep inside the dc analysis form — not in Sweeps & Ranges.

  1. Analyses → Choose… → dc. Tick Save DC Operating Point.
  2. In the same form, tick Sweep Variable → Temperature.
  3. Sweep Range = Start -20, Stop 85. Sweep Type = Linear, Number of Steps = 22 (≈ 5 °C per step).
  4. Leave Setup → Temperature at its nominal 27 °C — the sweep overrides it per point. Do not also add temperature under Sweeps & Ranges: that multiplies runs instead of producing one waveform, and ymax() then collapses to a single point per run.
  5. Corners: C0 only, per TB-01. A corner that sets its own temperature fights the sweep.
  6. Outputs → Setup… → add each row below with Type = expression. A bare signal name does not evaluate — that is the single most common cause of eval error in the results table.

Fastest way to get the names right: Outputs → From Design, then click the wire in the schematic. Typing them by hand is what produces unresolvable signals.

Which net names to use — they differ per testbench

Quantityanatop_tb_biasgen (TB-01, global cell)BiasGenCascWideSwing_tb (imported, local cascode cell)
N mirrorv("/bn!")v("/V_BNM")
N cascodev("/bnc!")v("/V_BNC")
P mirrorv("/bp!")v("/V_BPM")
P cascodev("/bpc!")v("/V_BPC")
The two cells are not interchangeable. anatop_biasgen publishes its rails as global nets (trailing !) with no output pins, so v("/bn!") resolves from anywhere in the hierarchy. The imported cascode cell (anatop_biasgen_local, ex-leon/BiasGenCascWideSwing) publishes ordinary pins, so its rails only exist on whatever net the testbench wires them to. Running TB-01's expression list against the imported TB gives four unresolvable signals and four eval errors.

Tempco expression

bn_tempco     = (ymax(v("/bn!")) - ymin(v("/bn!")))                          ; volts of spread, -20..85 C
bn_tempco_ppm = (ymax(v("/bn!")) - ymin(v("/bn!"))) / (value(v("/bn!") 27) * 105) * 1e6   ; ppm/C

TB-01's bn_tempco is deliberately a spread in volts, not a normalised coefficient — it is a pass/fail screen, not a datasheet number. Use the _ppm form when you need to compare against a spec. 105 is the sweep span in °C; value(… 27) samples the waveform at nominal.

Running it and viewing the results

  1. Select the test in the Data View pane so the edits land on it and not a sibling.
  2. In Outputs Setup, tick Plot on the four rail rows. Leave bn_tempco unticked — it is a scalar, it belongs in the table, not on a graph.
  3. Run (Simulation → Netlist and Run, or the green run arrow).
  4. Anything with Plot ticked opens automatically in ViVA when the run finishes. To plot after the fact, go to the Results tab, select the output rows, right-click → Plot. For raw nets that are not set up as outputs, use Results → Direct Plot → Main Form → dc → Voltage and click the wire in the schematic.
  5. To overlay all four rails on one graph, select all four and plot together; in ViVA use Append rather than Replace so each new plot adds to the frame.
The check that the sweep actually took. The plotted x-axis must read temperature, −20 → 85. If it comes back as a single point, or the x-axis is a design variable, the sweep did not apply — you almost certainly set it under Sweeps & Ranges instead of inside the dc analysis form. Scalar expressions such as bn_tempco never plot; they appear as a number per corner in the Results table, and a blank cell there means the expression failed to evaluate, not that the value is zero.
Two quirks in the imported testbench. V_MBNM is a pin on the symbol but is not labelled on any net in BiasDCOpTB — label the wire before you can probe it by name. And the schematic carries a label V_BCP alongside V_BPC; V_BCP matches no symbol pin, so confirm it is intentional and not a transposed-letter typo leaving a node floating.

TB-03 · anatop_tb_tiaamp — A2 core, the class-A concern

DUT: anatop_tiaamp (bts_pmos: vinp vinm vout TCBias<5:0> LCBias<5:0> En; supplies via vdd!/vss!). TB-05 · anatop_tb_dac — 14-bit R-2R vref/vcm DAC

DUT: anatop_dac (En, A<13:0>, Out). Load in mission mode is an amplifier gate — model with 1 pF.

Schematic — the binary-counter bus drive (full-ramp method)

14 × analogLib/vpulse, one per bit, wired to labels A<0>…A<13>. With step time Tb = 2e-6 the ramp walks all 16384 codes in 32.8 ms:

Bit iv1 / v2delayrise = fallpulse widthperiod
A<i>, i = 0…130 / vdd25Tb·2^i1nTb·2^i − 1nTb·2^(i+1)

Concretely: A<0>: delay 2µ, width 2µ, period 4µ · A<1>: delay 4µ, width 4µ, period 8µ · … · A<13>: delay 16.384m, width 16.384m, period 32.768m. Code n is stable during [n·Tb, (n+1)·Tb].
