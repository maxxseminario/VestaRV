F-2 · FIXED anatop_pixel — the ADC mux select

Both halves of the fix were made. A new input pin SARADC_SEL<3:0> was added to schematic and symbol, and it drives the mux in the correct bit order — which the port-order mapping settles without ambiguity:

subckt anatop_amux_16 A<0> … A<15> Sel<3> Sel<2> Sel<1> Sel<0> Y …
    ADC_MUX (V_OUT V_CM V_PATTERN net32 ATP vss! net35 … net44
             SARADC_SEL<3> SARADC_SEL<2> SARADC_SEL<1> SARADC_SEL<0>
             ADC_IN …) anatop_amux_16

so Sel<k> ← SARADC_SEL<k> and adc_sel = k selects slot k. The reversal the first edition warned about (net46<0:3> against Sel<3:0>) is not present.

Measured: with adc_sel = 0, ADC_IN equals V_OUT to the last stored digit at every one of px_dc's 32 codes — max |ADC_IN − V_OUT| = 0.000e+00 V — against −0.27 µV floating before. The mux and its select are done. What is not done is the conversion: see §7.4.

F-3 · OUTSTANDING ATP_MUX has sixteen floating inputs

net1, net2, net14…net27 each still have a single connection — the mux input they sit on. The analog test point therefore selects between sixteen undriven nodes, and ADC_MUX.A<4> = ATP inherits that. Harmless to convergence (Spectre resolves them through gmin) and useless as a test fabric. Now that the select pin exists, the ATP path is the only remaining reason the debug fabric cannot be exercised.

F-4 · OUTSTANDING The DAC supply regulators are still not in the supply path

DAC_VCM_PSU (En_Dac_Vcm VDD_DACVCM inh_vdd inh_vdd_sub inh_vss inh_vss_sub) anatop_pixel_dac_psu
DAC_VCM     (A_Dac_Vcm<11> … En_Dac_Vcm V_CM inh_vdd inh_vss) anatop_pixel_dacR2R12

Unchanged: VDD_DACVP and VDD_DACVCM appear on no other instance, and both DACs take inh_vdd, i.e. the global vdd!. The owner took neither option — the regulators are neither in the loop nor deleted.

Consequence for every potential number in this document. The DACs are fed from an ideal 2.5 V rail, so the 25.8 mV supply modulation measured on tb_anatop_pixel_dacR2R12 — against a 133 µV budget — is still not exercised. That is why RE tracks to 0.6724 mV rather than to tens of millivolts. It is a missing stimulus, not a good result, and it is unchanged from the first edition: the F-4 decision does not move any number here until it is made. Had the regulators been placed in the loop, the whole potential axis would have inherited a code-dependent term of order 25.8 mV — roughly 40× the tracking error currently reported, and enough to dominate every entry in §8.1.

11 · Next steps toward tapeout verification

11.1 Verified

  • The pixel netlists, converges in dc and in transient, and has zero unbound instances.
  • Both 12-bit DACs, their code decode, their enables and their absolute accuracy at the two endpoints and mid-scale.
  • The A1 control loop through the real DAC over the full 0 – 2.42 V potential range.
  • The Rf code path — all 320 codes, both decoders, both seams.
  • The A2 loop, its offset and its input bias current, on the owner's schematic — no longer netlist-level.
  • The ADC source mux and its select pin — bit order, slot map, and pass accuracy (zero error at dc).
  • The bias generator and its 6-bit trim, implicitly: both amplifiers reach their design operating points at b6_BiasAdj = 37.
  • The full-chain staircase voltammogram, and the readout equation against the in-line probe.

11.2 Not verified

  1. The conversion, at schematic level. The CDAC has no devices there, so adc_code from the Maestro tests is not a measurement and never will be. Every quantitative ADC statement has to come from an --adc-extracted run (§7.5), which is a separate, clearly labelled experiment — the full switchViewList swap would also take anatop_tia_amp_ab, anatop_pixel_dacR2R12 and anatop_pixel_dac_psu to their extracted views and move every other number in this document.
  2. The readout, through a real measurement. §7.5 exercises the converter against known voltages, not against a current. Nothing yet reads a voltammogram back through the on-chip ADC, and the calibration slot it would need is broken (§7.5, the vcm-tap finding).
  3. Stability. No stb and no ac test exists on the assembled pixel. The flat bench's PM 89–93° was measured with an ideal Rf and an ideal vref; neither is true here.
  4. Corners. Nominal only.
  5. Monte Carlo. Not attempted, and not ready: the model section is castalia_typ_25 (no statistics), and anatop_tia's two mimcap_sin still carry mismatchflag=0 (F-5b). Both must change before an MC run means anything — this is the failure mode that produced a tidy, wrong distribution twice before.
  6. Noise. Nothing. in_rma at maximum gain is the open specification and it is 2–10× over budget on the flat bench.
  7. The test fabric. F-3 leaves the ATP mux with nothing to look at, and it is now reachable through the fixed select — so the debug path selects sixteen floating nodes on demand.
  8. Power. No supply-current output on any test.

11.3 In order

  1. Buffer the vcm tap into the ADC mux (§7.5). This is the new blocking item. Sampling V_CM through the mux collapses the channel for microseconds at every conversion, and V_CM is the node the whole gain-independent zero calibration rests on. Same cell the RE tap needs (F-5c) — one decision buys both.
  2. Record the bit-9 inversion in the register map. The raw data bus is code_msb's complement in bit 9. It is a two-line note in firmware and a silent 512-code error if it is missed.
  3. Decide F-4 — regulator in the path, or delete the instances. The 25.8 mV finding has no path to silicon either way until this is settled, which also answers the build guide's §9 item on VddDac. It is the largest unmodelled term in every potential number here.
  4. Wire the ATP mux inputs (F-3) and add the RE buffer that slot 3 wants (F-5c). Now that the select works, the debug fabric is not decorative but actively misleading.
  5. Add a px_stb test: stb on IPRB_F and on IPRB1 across the electrode grid the flat bench used (cdl_we {100n, 1u, 10u} × rct {10k, 1M}) at N = 0 and N = 319. The programmable ladder in the feedback path is new to the loop and has never been simulated inside it.
  6. Make the setup MC-ready — section castalia_pm_25, mismatchflag=1 on the mimcap_sin pair (F-5b) — then repeat the flat bench's zero-offset MC on the assembled pixel. The flat bench's σ(vre,zero) = 5.72 mV is the number to reproduce or improve.
  7. Give A2 its en pin (F-5a) before the four-channel top, where per-channel power-down is the whole point of having one.
  8. Corners last, and only on the tests whose result they can move.

11.4 Against the channel-build guide's plan

Beyond F-5, three planned items are absent from the tapeout cell and each needs a decision, not a simulation:

  • The ADC_SEL path now exists, under another name and one bit wider. The guide drives the ADC mux from AFE_ADCSRCSEL[2:0]; the pixel's pin is SARADC_SEL<3:0>, 4 bits for a 16:1 mux. The register map needs the extra bit, or the mux needs to shrink to the anatop_amux_8 the guide asks for (F-5d).
  • No RE buffer. Slot 3 is specified as t_re_buf precisely because the guide rejects sampling the raw electrode. D-1 (which cell) is still open.
  • No SW_WE/SW_CE isolation switches and no on-chip calibration resistor (guide §3.4, D-2, D-4). The pixel connects CE/RE/WE straight out.
  • Per-channel vcm DAC. The cell instantiates its own DAC_VCM; CLAUDE.md's four-channel plan has the vcm DAC shared. Four DACs is the more accurate and the more expensive arrangement — confirm which one the floorplan is being drawn to.

12.1 Traps hit while building this

  1. OSSHNL-109 from one un-checked cell three levels down aborts the netlist of the whole hierarchy, and the ADE error that surfaces is only "Failed to create netlist." The real message is in …/netlist/si.foregnd.log.
  2. A design variable and a net cannot share a name: e0 is the electrode's formal potential, so the ResEn bit nets had to be rsel0…5.
  3. outputList and envSaveOptions sit in the same ADE component but in either order depending on the state file — three of the four donor blocks had envSaveOptions first. Replacing the component wholesale drops the save options and the netlist silently reverts to save=allpub; the splice has to bound the outputList element with a depth-aware scan and patch the partition wherever it is.
  4. Cloning tb_anatop_pixel to tb_anatop_pixel_top makes the source name a prefix of the destination, so the cloner's residual check reports every edited file. Grep for the whole token.
  5. In a per-bit PWL bus drive, every bit ramps over the same t_edge, so mid-ramp the bus sits at VDD/2 and the receivers are ambiguous. At t_edge = 20 µs the 12-bit DAC glitched to full scale on 1 % of every tread and Spectre reported zero errors. 20 ns fixes it.
  6. scale= on a vsource type=pwl was not worth proving; the levels are written as literal volts.
  7. An OA connectivity query before Check-and-Save is not evidence. Read cold, the fixed anatop_pixel reported SARADC_SEL<3:0> with zero instTerms and ADC_MUX.Sel still on net46<0:3> — i.e. it said the owner had added a dead pin. The extraction was stale, not the design. schCheck first, then read.
  8. schCheck catches shorts that the unbound/unconnected audit cannot. Placing the new V_DS row 1.0 apart instead of 2.0 shorted four dsel nets and CLK to vss! (SCH-7064); every terminal was still connected, so the builder's own audit returned 0. Read the schCheck pair.
  9. Bus subscripts must be escaped in a spectre save line. A bare save D<0> parses < as an operator and spectre dies at read-in with SFE-874. Write D\<0\>.
  10. The extracted converter needs a strobeperiod. Its femtosecond timesteps wrote 5.7 GB of psfascii for a 21 µs transient with 13 saved nets, on a filesystem with 207 GB free. strobeperiod=5n takes it to 64 MB and changes the output grid only.
  11. The SAR data bus is valid only while RDY is high — a 100 ns window at 17.755 µs with the bench's stimulus file. Outside it the bus reads a flat 1023, so a probe time chosen anywhere else returns a number that looks like a code and is not one. t_probe = 17.8 µs is dead centre and was right by construction.
  12. simstim/adc/adc_stim_gated.txt is stale. It describes the superseded 1 MHz / SAMPLESTEP 0 stimulus (aperture 7.5 µs, 16 µs conversions); the .pwl beside it was regenerated 2026-08-20 from the RTL at 20 MHz / SAMPLESTEP 7. Trust the .pwl and the measured RDY edges, not the summary text.
  13. After the 2026-08-23 techBindTechFile repair, techGetTechLibName("castalia") returns nil — by construction, because a techfile was bound directly rather than a tech library. The binding is nevertheless correct: techGetTechFile(ddGetObj("castalia")) and techGetTechFile(ddGetObj("tsmcN65")) return the same db object and layer names resolve (M1 = 31, PO = 17). The standing advice to "check techGetTechLibName, not techGetTechFile" applies to the ddCreateLib default case and gives a false alarm on a techBindTechFile repair; compare the techfile object against tsmcN65's instead.

The five Maestro setups built this week — tb_anatop_pixel_top, tb_anatop_tia_rprog_loop, tb_anatop_dacsettle, tb_anatop_rebuf, tb_anatop_dac14 — carried an empty <specs> element, so the Results pane showed values and no pass/fail. skill/castalia_tia_tb_maestro.py drops the donor's specs when it clones a setup; nothing put them back. 46 specs are now written, 40 pass and 6 fail by design. 13.1 px_zero — root cause

The transient's stop field held VAR("t_stop"). OCEAN evaluates VAR() while netlisting, so the headless path resolved it to stop=t_stop and passed. The GUI's ADE netlister does not, and wrote the call through to Spectre: 
ERROR (SFE-1997): "input.scs" 3000: Cannot run the simulation because
tran: parameter `stop': Function `VAR' is not defined.
ic/cds.log, run Interactive.0 of 2026-08-23 15:13 — one simulation error, px_dc and px_gain unaffected because they sweep a design variable by name.

The two paths differ only here: a bare design-variable name netlists identically through both, an OCEAN function does not. VAR() stays correct in an output expression, where the calculator defines it — t_probe is still read that way.

13.5 Re-applying them

The spec tables live in the builder scripts, one per setup, each limit commented with its source. skill/maestro_speclib.py holds the splice, the XML shape and the checks. Specs sit only in maestro.sdb <active><specs> — active.state carries none, verified on all five setups and both donors — so unlike model libraries there is one place to patch.

python3 skill/pixtop_maestro_setup.py       --specs --apply
python3 skill/tia_rprog_loop_maestro_setup.py --specs --apply
python3 skill/dacsettle_maestro_setup.py   --specs --apply
python3 skill/rebuf_maestro_setup.py       --specs --apply
python3 skill/dac14_maestro_setup.py       --specs --apply
python3 skill/spec_summary.py simruns/specs_verify_20260823/*/

Specs mode writes <active><specs>, bare-names any VAR() left in an analysis field, and (on pixtop) drops the alien <parameters> block. It touches nothing else, re-parses every file as XML before writing, and keeps a one-shot .bak.specs. A full --apply run of the same builder now writes the specs too, so a rebuild from scratch does not lose them.

Close the Assembler before running any of this. A live Virtuoso writes its in-memory copy back over an edited setup, and it renames the state snapshot as it goes — the owner's 15:13 session replaced test_states/Interactive.32.state with Interactive.0.state and repointed the sdb. The scripts read the sdb's current pointers rather than a hard-coded name, and refuse to run if maestro.sdb.cdslck exists, but a session that is open and idle holds no lock.
