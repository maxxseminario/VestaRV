Chip Configurator
interactive front-end for make chip · VestaRV / Castalia · TSMC 65 nm
1Adjust the knobs below (steppers − +, toggles, dropdowns) — everything updates live. → 2Download config.json from the panel on the right. → 3Run make chip CONFIG=config.json in platform_castalia/.
🏷️

Chip identity

the only knob wired straight to the Makefile
Chip name
Renames the chip in the TRM & generated headers (docs-only; RTL stays byte-identical). Passed as CHIP_NAME=.
🧩

Cores & harts

drives numHarts, the shared arbiter fabric & the multi-core TRM chapter
Number of harts
Each hart is an identical VestaRV tile with a private 16 KiB TCM. >1 instantiates the round-robin arbiter, CLINT, mutex bank & IRQ router.
Register file
Dual-port regfile (ASIC synthesis). Single-port for Spartan-6 FPGA targets.
⚙️

ISA extensions

real hardware knobs — disabled arms are pruned at elaboration & trap as illegal instructions
🧠

Memory

ROM, per-tile TCM, shared bulk RAM & NPU staging
🔌

Peripherals

the shared 0x4000 peripheral window (all harts, behind the arbiter)
Preview / planning only. The peripheral set is fixed RTL template content — make chip does not add or remove peripherals from a config file (yet). These counts shape the summary & memory picture; they are recorded in config.json under peripheralsPreview but ignored by the generator. Cores, ISA, register file & RAM sizes are applied.

      How this works. Download config.json and run
      make chip CONFIG=config.json from platform_castalia/.
      generate.py reads the file (via the CHIP_CONFIG env the Makefile passes) and
      applies its knobs — chip name, hart count, register file, ISA generics, RAM-region sizes — over the
      Castalia defaults; missing keys keep their default, so a partial file is fine. The peripheral set and the
      hart/arbiter instances are fixed RTL template content and are not changed by a config file.
      The make command and generate.py (manual) tabs are there if you'd rather not use a file.
      With the default config, check_mcu_vhd.py stays byte-identical to hdl/MCU_MP.
