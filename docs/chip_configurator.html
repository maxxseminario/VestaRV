Chip name
Renames the chip in the TRM & generated headers. At the Castalia defaults the RTL stays byte-identical regardless of name (check_mcu_vhd.py).

Cores & shared fabric

drives the hart tiles, arbiter widths, CLINT layout & IRQ-router rows in the generated MCU.vhd
Number of harts numHarts
Identical VestaRV tiles, each with a private TCM. 4 = Castalia golden master (byte-identical RTL); 18 = Argus (boots all harts in simulation). Other counts emit well-formed but unverified VHDL.
Orchestrator hart orchestrator
Castalia-Penta: make HART 0 an always-on soft orchestrator instead of a hardened corner tile, and turn every other hart into a uniform channel tile. Hart 0 is emitted as orch_tile, keeps the flash/XIP + boot + trap + a0 wiring it already had and sits outside the power-gating fabric; harts 1..N-1 all gain PWRCR gate bits. Also switches the memory map to v2: SH_AW ≥ 16, one read-only TCM aperture per hart at 0x20000 + 0x4000·h (management hart only), extended flash at 0x40000. Off = today's chip.
Hardware mutexes numMutexes
Word-mapped claim-on-read mutex bank at 0x6000. 16 (Castalia) and 32 (Argus) are the proven points.
Register file registerFileDualPort
Dual-port regfile (ASIC synthesis). Single-port for Spartan-6 FPGA targets.

Peripherals

the shared 0x4000 peripheral window (all harts, behind the arbiter)
Applied vs. preview. The NPU toggle is real (peripherals.npu): off = Argus-style chip with no NPU and no 0xC000 staging window. CLINT / mutex bank / IRQ router are always instantiated (the multi-core fabric). The counter pills (GPIO/SPI/UART/TIMER/I²C) are planning aids only — the peripheral set is fixed RTL template content and they are not exported to config.json.

Live diagrams

rendered from the same knobs; the TRM gets the pdflatex/TikZ versions of these
Hart tiles couple an unmodified VestaRV core with a private TCM behind a registered boundary; everything else is reached through the serializing round-robin mp_arbiter. Hart 0 alone owns the SPI-flash XIP path.
M12 single-ROM boot: every hart resets to PC 0x0 in the shared ROM and dispatches on mhartid. Tiles park in low-power sleep until loaded through their mailbox row (0x10500 + 16h) and a CLINT software interrupt.
Derived, not configured: the pad ring comes from the package model in generate.py (_PACKAGE_MODELS: pin order, sides, power domains) — the same model that emits the TRM pinout figure, config/PadRing.json, and the out/pnr/chip_top_padring.tcl pad-placement template at every build. It is rendered here straight from VESTA_DATA.packages[model] for any N pins/side QFN. Shaded pads are power rails, electrode/analog pads are tinted, GPIO pads carry their AF0 (reset) function.

      How this works. Download config.json and run
      make chip CONFIG=config.json from platform/common/. The schema is
      validated by generate.py: unknown keys and out-of-range values are hard errors, so a typo
      can never silently fall back to a default. Applied knobs: chip name, hart count, mutex count, register
      file, the ISA switches, the memory-region sizes, and NPU presence — they drive the generated
      MCU.vhd/MemoryMap.vhd/riscv_tb.vhd, the headers and linker scripts,
      and the TRM PDF (feature list, config tables, block/boot/sync/pinout diagrams). Every build also writes
      config/ChipConfig.resolved.json (knobs + derived geometry — make show prints it) and
      config/PadRing.json (the derived pad ring). With the default config the generated RTL stays
      byte-identical to hdl/common (check_mcu_vhd.py exit 0).
