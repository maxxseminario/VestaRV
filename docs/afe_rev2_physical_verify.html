Castalia AFE rev-2 — analog physical verification (DRC / LVS)

Run 2026-08-24 · Library castalia (tsmcN65, IC618) · Calibre celldrc + Pegasus LVS · Companion to afe_rev2_strategy.html, afe_rev2_eis.html, afe_rev2_pixel_verify.html.
First physical verification of the analog side. 37 castalia cells carry a layout view; 36 streamed, 36 ran DRC, 36 ran LVS.

Headline. 15 of 36 cells are DRC-clean and 25 of 36 are LVS MATCH. Of the 21 dirty DRC cells, 14 report nothing but minimum-density and latch-up guideline rules, which a standalone cell cannot satisfy; 7 carry real geometry violations. Two defects dominate: a 2 nm off-grid placement of the SAR instance inside anatop_pixel that alone generates 550 242 of the run's 550 268 DRC results, and the anatop_pixel layout carrying 9 pin labels against 75 schematic ports. Both are single-edit fixes.

1 · Safety — the ingest hazard

NEVER ingest castalia. ~/vestarv/signoff_mp/ingest_layout.sh line 74 is rm -rf "$lib", and the signoff Makefile's drc:, ant:, lvs: and signoff: targets all depend on ingest. A single make drc LIB=castalia (or ./ingest_layout.sh castalia …) deletes ~/chips/castalia/ic/castalia, which is hand-authored source with no git backup and no other home. There is no undo.
  • The ingest target library must always be a new, disposable name. The convention established by this run is castalia_sign, created under ~/vestarv/signoff_mp/ and safe to delete at any time.
  • ~/chips/castalia/ic is streamed out of, read-only. Nothing in this flow writes there; every artifact lands in scratch or in ~/chips/castalia/simruns/.
  • ~/chips/myshkin/ic (frozen tapeout) is read for decks and for the reference LVS results only.
  • Echo the command and read the first argument before every ingest.

The one ingest actually performed in this run, verbatim:

cd ~/vestarv/signoff_mp
./ingest_layout.sh castalia_sign anatop_biasswitch_casc <scratch>/gds/anatop_biasswitch_casc.gds
#                  ^^^^^^^^^^^^^ disposable lib, NOT `castalia`

2 · Flow, and why it differs from the digital path

Every existing BLOCKS entry in the signoff Makefile is a digital block: an Innovus GDS ingested into a signoff OA library, DRC'd with blockdrc, and LVS'd against a Verilog netlist through v2cdl. None of that shape fits an analog leaf cell, so no BLOCKS entries were added; the runners were called directly with explicit library/cell arguments. Three deviations, each justified:

  1. Per-cell stream, not library-wide. A single strmout -library castalia -view layout aborts at structure 538 on castalia/OpAmpCurrentMirrorP/layout (XSTRM-341, see §9). Per-cell streaming isolates that failure to one cell.
  2. Calibre driven off the GDS for the ADC-bearing cells, not off an OA library. ingest_layout.sh calls strmin_gds.sh, whose -refLibList carries myshkin_tapeout. The SAR sub-cells (Comparator_2V5_Mei, Cap_DAC_2V5_D_0p13s_0p70lsb, Cap_DAC_Driver_2V5_r1, Sample_Switch_2V5_r1, LS*TO*, DFF*_Spacing_Modded, Logic_Main_Neg_Out_Only_Sync) carry the same names in myshkin_tapeout, so strmin would reference that library's masters instead of translating ours — the PG4 phantom-geometry class. strmin_gds.sh's own gate correctly refuses, and it is right to. drc.sh's first act is to strmout the OA library back to a GDS, so handing Calibre the streamed GDS directly is the same input with one fewer name-resolution hazard. Cross-checked on anatop_tia_amp_ab: the ingest path and the direct path produce byte-identical rule statistics.
  3. LVS uses an auCdl schematic netlist, not lvs.sh. lvs.sh takes a Verilog .lvs.v and converts it with v2cdl; there is no Verilog for an analog cell. The precedent is Myshkin's own analog flow (~/chips/myshkin/ic/pvs/lvs_cdl_only and the run dirs under pvs/potentiostat_final/): si -batch -command netlist with simSimulator = "auCdl" produces the source CDL, and pegasus -lvs -check_schematic compares it against the streamed layout. That template (pvs/si.env) was reused unmodified.

3 · Procedure — DRC

Deck: celldrc = /home/mseminario2/chips/myshkin/ic/calibre/celldrc.rul, the CLN65S_9M_6X1Z1U v2.5a deck with FULL_CHIP off. The local decks/blockdrc.rul (main.rul v2.6_2a) also has FULL_CHIP off but exists specifically for blocks containing sram1p16k_hvt_pg; nothing analog needs it. With FULL_CHIP off, CHECK_LOW_DENSITY stays off, so the deck choice does not change the result for any cell here — the density rules that do fire (*.DN.*) are unconditional in both decks.

  1. Source the environment and build a read-only view of the castalia library chain, so no tool ever runs with ~/chips/castalia/ic as its working directory: 
    source ~/vestarv/cdspaths.sh
mkdir -p $PV && cd $PV
cat > cds.lib <<'EOF'
INCLUDE /home/mseminario2/chips/castalia/ic/cds.lib
EOF
  2. Enumerate the cells that have a layout view: 
    ( cd ~/chips/castalia/ic/castalia && ls -d */layout ) | sed 's#/layout##' | sort > cells.txt
  3. Stream each cell out, full hierarchy, read-only: 
    strmout -library castalia -topCell $c -view layout \
        -strmFile $PV/gds/$c.gds -techlib tsmcN65 \
        -layerMap /opt/design_kits/TSMC65-PDK/tsmcN65/tsmcN65.layermap \
        -logFile $PV/log/strmout_$c.log
    Verify: rc=0, non-zero file, no ^ERROR in the console. 36/37 pass; OpAmpCurrentMirrorP fails (§9).
  4. Ingest into the disposable library and run drc.sh — the sanctioned path, used for the 33 cells whose hierarchy has no myshkin name collision: 
    cd ~/vestarv/signoff_mp
./ingest_layout.sh castalia_sign $c $PV/gds/$c.gds
./drc.sh           castalia_sign $c celldrc
# report: calibre/castalia_sign/$c/results/celldrc.rpt
    ingest_layout.sh rm -rfs its target on every call, so castalia_sign holds exactly one cell at a time; the per-cell report directories under calibre/castalia_sign/ persist.
  5. For anatop_pixel, anatop_pixel_adc and NEW_ADC_Main_2V5_Sync_0p13s_0p70lsb, run Calibre on the streamed GDS (scripts/analog_drc.sh in the archive, same runset as drc.sh): 
    ./analog_drc.sh $PV/gds/$c.gds $c celldrc $PV/direct/$c
  6. Read the verdict from TOTAL DRC Results Generated: and the per-rule table under RULECHECK RESULTS STATISTICS (BY CELL). Never read a .rc file.

Runtime: 4–9 s per cell, whole sweep under 4 minutes. Licenses are shared; the sweep is serial.

4 · Procedure — LVS

  1. Re-stream every layout with pin text — the DRC stream has none, and without labels Pegasus has no port correspondence to seed on: 
    strmout -library castalia -topCell $c -view layout \
        -strmFile $PV/gds_lvs/$c.gds -techlib tsmcN65 \
        -layerMap /opt/design_kits/TSMC65-PDK/tsmcN65/tsmcN65.layermap \
        -convertPin geometryAndText -noWarn "20 32 33 35 315" \
        -logFile $PV/log/strmoutlvs_$c.log
  2. Instantiate Myshkin's auCdl template per cell and netlist the schematic. si must run from a directory holding a cds.lib that resolves castalia; it only opens cellviews for read: 
    sed -e "s/\$lib/castalia/g" -e "s/\$cell/$c/g" \
    < ~/chips/myshkin/ic/pvs/si.env > $PV/lvs/$c/si.env
cd $PV && si $PV/lvs/$c -batch -command netlist
    Output: castalia.$c.schematic.cdl. A .simrc in the same directory declares powerNets/groundNets.
  3. Compare with Pegasus and the stock kit deck. The kit's source.added is mandatory — without it every cell containing rppolywo, rnpolywo or mimcap_sin dies with ERROR (NVN-13010): Cell <x> is not defined and rc=1 (12 of 36 cells on the first pass): 
    cd $PV/lvs/$c
pegasus -lvs -check_schematic \
  -gds $PV/gds_lvs/$c.gds -layout_top_cell $c -source_top_cell $c \
  -source_cdl /opt/design_kits/TSMC65-PDK/kit/PVS/LVS/DFM_LVS_RC_PVS_N65RF_1P9M_ALRDL_v1.6b/source.added \
  -source_cdl $PV/lvs/$c/castalia.$c.schematic.cdl \
  -run_dir $PV/lvs/$c \
  /opt/design_kits/TSMC65-PDK/kit/PVS/LVS/pvs.lvs
  4. Read Run Result from lvs.rep.cls. Pegasus exits 0 on MISMATCH — the exit code is not the verdict, exactly as lvs.sh's 2026-08-24 header warns. The useful detail is the CELL COMPARISON block: the Pins and Nets rows of STATISTICS, then MISMATCHED INSTANCES / UNMATCHED SCHEMATIC PIN LABELS / SHORTS AND OPENS.

Runtime: 2–4 s per cell.

6 · Reading the rule families

FamilyWhat it isVerdict
*.DN.*
M1–M9.DN.1/2, OD.DN.2, PO.DN.2		 Minimum layer density measured in a 20 µm or 150 µm window (DENSITY … WINDOW … INSIDE OF LAYER CHIPx). artifact A cell smaller than the window, or with no M8/M9 at all, can never pass. Meaningful only after the cell is placed in a chip that carries fill. Ignore at cell level; re-check at top.
G.1:* OFFGRID <layer> 5 — every vertex must land on the 5 nm grid (DB precision 1 nm). real Fires only on anatop_pixel, and there from a single cause (§8, fix 1).
G.4:M1i M1 edges shorter than minimum width with a vertex count > 4 — small jogs and notches. real Hand-drawn M1 artefacts, all in imported leon cells. Cosmetic-to-yield, not a short; fix by squaring the jog.
LUP.6 Latch-up guideline: any point in a MOS source/drain must be within LUP_6 of a well/substrate strap of the same well. context Enabled by #DEFINE GUIDELINE_LUP in this deck. A leaf cell that expects the parent to supply the guard ring will always fire. Re-check inside anatop_eis before treating as real.
SUGGESTED.NW.S.3__NW.S.4 Conservative N-well spacing, enabled by #DEFINE NW_SUGGESTED. optional Not a required rule. The hard NW.S.1/2/3/5/6/7 results on anatop_eis_cbia are separate and are real.

8 · Prioritised fix list

  1. Snap the SAR instance in anatop_pixel to the 5 nm grid. The instance anatop_pixel_adc sits at (44.260, 115.997) µm. The Y is 2 nm off a 5 nm grid; every shape in the ADC's subtree therefore reports off-grid, and that single placement produces 550 242 of the cell's 550 268 DRC results. Move it to 115.995 or 116.000 and re-run. Verify afterwards whether the residual M1.A.1×9, NW.S.5×2 and M1.S.1×1 also clear — 2 nm slivers at an abutment are the obvious suspect. Command to re-find the offender: 
    python3 scripts/offgrid_scan.py $PV/gds/anatop_pixel.gds     # archived with this run
  2. Label the anatop_pixel boundary. 9 pin labels against 75 schematic ports. Until the digital control, DAC-code, ResEn/ThEn and SARADC_* buses carry pin text, the pixel LVS verdict carries no information. This is the single blocker on a meaningful top-level analog LVS.
  3. anatop_eis_ota_p: add the bn! label. One label from MATCH, all 52 devices already correspond. Confirm which physical rail is the NMOS bias in that layout before labelling — this is the bn!/bnm! collision CLAUDE.md flags as open, and labelling the wrong rail would bury it.
  4. anatop_biasgen_local / anatop_eis_biasgen: resolve the extra NMOS at (27.045, 0.770). Everything else matches. Either it is an undocumented dummy/decoupling device that belongs in the schematic, or it is a stray.
  5. Label anatop_eis_cbia, anatop_eis_cbia_tia, anatop_eis_ota_sn. Zero pin text; nothing about those three can be concluded until they have labels. ota_sn already agrees 9:9 on devices and will probably match immediately.
  6. anatop_eis_idac: 205 action-required DRC results and 242 unmatched schematic devices. The largest genuine defect count in the set, and the only cell where DRC and LVS both point at real geometry. Off the tapeout channel — schedule it with the EIS island, not before.
  7. anatop_eis_cbia: 39 action-required DRC results (NW/OD2 spacing, M1 minimum area). Same schedule.
  8. G.4:M1i small-jog cleanup — 137 in anatop_eis_idac, 10 each in anatop_eis_ota_p and anatop_eis_tgate_amux16, 6 in anatop_eis_biasswitch, 4 in anatop_eis_tgate_p2. Low severity, high count; batch it.
  9. Repoint OpAmpCurrentMirrorP's layout (§9), or delete the cell if the current-mirror OTA is no longer a candidate.
  10. Re-check density and LUP.6 at assembly, not now. Nothing on the *.DN.* or LUP.6 lists is actionable at cell level.

9 · Not run, and why

  1. OpAmpCurrentMirrorP — no DRC, no LVS. Its layout view instantiates potentiostat_final/BiasSwitchCascode/layout, and potentiostat_final does not exist on disk (the known dangling-library break). strmout aborts: 
    ERROR (XSTRM-341): Translation failed while processing 'castalia/OpAmpCurrentMirrorP/layout'
because of the following reason: Cannot open design potentiostat_final/BiasSwitchCascode/layout:
"Library potentiostat_final not found."
    The instance header carries three historical fallbacks — potentiostat_final, socdemo_adc, teewinot — none resolvable. castalia_anatop_repair.il repointed schematic instance headers only; layout headers were left broken. The replacement master already exists in the library as anatop_biasswitch_casc (which is itself DRC-clean and LVS MATCH), so the repair is a one-line repoint. This also aborts any library-wide strmout, which is why the sweep streams per cell.
  2. anatop_tia_rprog — no layout view exists. Confirmed against the library: the cell has schematic and symbol only, consistent with CLAUDE.md's "no layout (source layout is the 223-unit cell)". Nothing to verify. Its ancestor anatop_eis_rprog_lpf2 was verified: DRC density-only, LVS MATCH — which is the best available evidence that the resistor ladder style is physically sound.
  3. Antenna (ant25) not run. Antenna ratios are a routing-length property measured against the full net, including the parent's routing. A standalone leaf run would report only artifacts. Schedule it on anatop_pixel after fix 1, and at chip level.
  4. anatop, anatop_channel, anatop_pstat, anatop_tia — schematic only. These four assembled blocks have no layout view, so there is nothing to verify. anatop_pixel is the only assembled analog cell with layout.
  5. ERC not evaluated. Pegasus wrote erc.sum for every cell but reports "Empty, non-executed ERC operations exist" — the stock kit deck's ERC checks need connectivity seeding this flow does not supply. Not a gap worth closing before the labelling fixes.

10 · Traps hit

  1. A library-wide strmout is all-or-nothing. It translated 538 structures and then discarded the run on one unresolvable master. Stream per top cell.
  2. strmin's PG4 gate fires on the SAR sub-cells, correctly. Nine Better_ADCs cell names collide with myshkin_tapeout; the gate refuses rather than let them resolve to the other chip's masters. Do not "fix" this by widening the cellmap — bypass strmin instead, or the phantom-geometry class comes back.
  3. Pegasus needs the kit's source.added for PDK passives. Without it, rppolywo, rnpolywo and mimcap_sin are undefined, pegasus exits 1, and the sweep reports "no verdict" on 12 of 36 cells — a failure mode that looks like a tool problem rather than a missing include.
  4. Pegasus exits 0 on MISMATCH. The exit code is not the verdict. Read Run Result from *.cls.
  5. set -u before source ~/vestarv/cdspaths.sh kills the script silently. The environment script trips an unbound variable and the shell exits with rc=1 and no output. Source first, then set -u.
  6. drc.sh greps its own strmout log case-insensitively for "error" and so prints "strmout reported errors:" for the benign line Translation completed. '0' error(s) — the same false alarm lvs.sh was already patched for. Harmless, but do not read it as a failure.
  7. The owner's Virtuoso (pid 61745) was live throughout and saved anatop_tia_amp_ab/schematic at 04:04:44, mid-sweep. The auCdl netlist for that cell was cut at 04:08:49, so the comparison used the newer schematic against a layout that was not touched — but a concurrent GUI save is a real staleness hazard for this flow, and the streams and netlists are not timestamp-gated the way lvs.sh gates its labels. This flow took no OA locks in castalia (verified: no *.cdslck under the library) and wrote nothing there.
  8. The DRC stream and the LVS stream are different files. DRC does not want pin text; LVS cannot work without it (-convertPin geometryAndText). Reusing one for the other silently degrades the LVS to an unseeded comparison — which is exactly the state three leon cells are in for a different reason.
