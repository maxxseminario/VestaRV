Castalia AFE rev-2 — corner-methodology audit: the passives never moved

Written 2026-08-25 · Library castalia (tsmcN65, IC618, Spectre 20.1) · Runs archived in ~/chips/castalia/simruns/cornaudit_20260825/.
Companions: simruns/bgladder_20260825/README.md (first catch), simruns/eiscorner_20260825/README.md §2.5 (second catch), afe_rev2_montecarlo.html §2 (the model-section families).

Result. The imported tsmcN65_typ_<c> corner family assigns the corner letter to the 16 MOS rows only: cor_res.scs stays tt_res, cor_mim.scs stays tt_mim and cor_rtmom.scs stays tt_rtmom in every corner. Eighteen of the twenty-three corner-carrying setups in ic/castalia use that family. The poly sheet resistance is a ±35 % quantity and it sets both Rf and the RSET of the bias generator that biases every amplifier in the corpus, so the published corner boxes of TRM §8.3, §8.4, §8.4.2, §8.5, §8.6 and §8.10 are understated by 1.4× to 157×. §8.8 (ADC) and §8.6.5 (mux) are false positives and stand; §8.9 and the Monte Carlo tables were always correct.

1 · Mechanism, in three sentences

Each tsmcN65_typ_<c> corner is a 46-row Model Files table in which only the sixteen MOS rows take the corner letter, and cor_res.scs, cor_mim.scs, cor_rtmom.scs, cor_disres.scs and cor_mos_cap*.scs are left at their tt_ sections. Poly sheet resistance therefore does not move across ff/fs/sf/ss, which pins both the transimpedance resistor Rf and the RSET that sets the reference current of anatop_biasgen_local, and with it the tail current, gm, bandwidth and supply current of every amplifier that the corpus corners. Everything a published corner column says about those quantities is the spread of the MOS alone, and freeing the poly rows widens it by 1.4× to 157× depending on the block.

2 · Why the kit made it easy to get wrong

The TSMC families are asymmetric. cor_std_mos.scs and the fifteen other MOS files carry five sections each (ff fs sf ss tt); the passive files carry three:

$ grep -oE "^section [a-z_0-9]+" /opt/design_kits/TSMC65-PDK/models/spectre/cor_res.scs
section ff_res
section ss_res
section tt_res

There is no fs_res and no sf_mim. Whoever imported tsmcN65_typ_fs and tsmcN65_typ_sf had no choice but to pin those rows; the table was then cloned to tsmcN65_typ_ff and tsmcN65_typ_ss, where a real section does exist, and the pin came with it. That is why the bias generator's fs and sf columns agree with the free matrix to three digits while ff and ss diverge by 47 % and 25 % — the two columns that were always going to be pinned are the two that are still right.

The kit has no cor.scs; the 1.0 V core MOS file is cor_std_mos.scs. The relative cor_*.scs rows Maestro emits resolve only against -I/opt/design_kits/TSMC65-PDK/models/spectre when a deck is run outside ADE.

The MIM capacitor behaves identically — cor_mim.scs is pinned at tt_mim in all four corners — and so does the MOM capacitor (cor_rtmom.scs). That doubles the nominal scope, but not the damage: the audit found no published corner number whose value a MIM or MOM capacitor sets (§4). The MIM gap is real elsewhere, though: castalia_pm_25 deliberately omits mc_mim, so the 13 mimcap_sin devices in the channel are bounded by neither the corner set nor Monte Carlo today.

8 · The corrected corner set

A correct 46-row family already exists in this library. Leon's imported tsmcN65_typ / tsmcN65_fast_best / tsmcN65_slow_worst on tb_anatop_eis_lpf/adexl carry ff_res, ff_mim, ff_rtmom, ff_disres and ff_mos_cap_25 (and the ss_ equivalents). They are the proof that the complete table is buildable in this kit; they are not directly reusable because they bundle temperature into the process axis (−25 / 25 / 75 °C), which the house convention keeps orthogonal.

Recommended fix, in order:

  1. Define the corner set once, as a file, not as a Maestro table. Add ic/models/castalia_cor.scs beside castalia_mc_models.scs, with one section per corner, each a complete 46-row include list against the master deck. One absolute path, one row in every Model Libraries table — exactly the pattern castalia_mc_models.scs already established for the MC sections, and for the same reason: a 46-row table that must be typed per setup will be cloned with its defects.
  2. Name the corners so the pin is visible. The passive families have no fs/sf section, so a five-corner axis cannot be uniform. Ship: castalia_tt, castalia_ff_all, castalia_ss_all (MOS + res + mim + rtmom + disres + mos_cap), and castalia_fs_mos, castalia_sf_mos (MOS only, passives at tt because the kit offers nothing else). A reader of a corner column then knows which of the two it is from the name.
  3. Keep ff_mos / ss_mos available as two extra sections. The MOS-only decomposition is genuinely useful — it is what separates §5's "the bias current moved" from "the transistors moved" — but it must be an explicitly requested point, never the default.
  4. Leave temperature on its own axis. 0 / 25 / 37 / 85 °C on castalia_tt, as tb_anatop_bg_startup already does. Note that the imported corners are defined at 25 °C while the nominal sits at 37 °C, so the existing tt-vs-corner comparison already carries a 12 °C confound; a corrected set should fix that at the same time.
  5. Import it everywhere, then verify from the executed netlist, never from the setup. After swapping a setup's corners, run one cheap test headlessly (skill/eis_headless_run.sh -c <cell> -v maestro -t <Test> -o <dir>) and check: 
    grep -E 'castalia_cor\.scs|cor_(res|mim|rtmom)\.scs' <dir>/.../input.scs
    The corner letter must appear on the passive rows. This is the same discipline the Monte Carlo readiness checklist already imposes, and for the same reason: the failure is silent.
  6. Close the MIM gap separately. castalia_pm_25 deliberately omits mc_mim, so after this fix MIM variation is covered by corners but still not by Monte Carlo. Either add a castalia_pm_25_mim section (the file already documents how) or state in §8.4 that the 22 pF compensation capacitor is bounded by corners only.

9 · What still stands, and what does not

No longer stands — do not quote these corner numbers.
  • §8.4.2 tab_tiaab_transfer — transimpedance, deviation from Rf, f−3dB, peaking. The bandwidth column is out by 18×.
  • §8.4.2 tab_tiaab_stability — worst-case loop PM is 61.5°, not 71.7°. fig_tiaab_zt and fig_tiaab_loopgain draw five curves at one Rf.
  • §8.4.2 tab_tiaab_accuracy gain error and INL, and tab_tiaab_noise's input-referred current noise, both of which divide by Rf.
  • §8.5 tab_px_acc35, tab_px_hg1m_acc — the headline rev-2 accuracy tables. Gain-set terms scale with Rf.
  • §8.5.2 tab_px_ctrl_stability, tab_px_ctrl_drive and fig_px_ctrl_loopgain.
  • §8.6.8 note_pixtop_power — the 432–914 µA analog-rail corner range. §8.6.6 note_pixtop_comp — the 72.37° slow-corner PM.
  • §8.4 tab_ampab_unity, tab_ampab_openloop, tab_ampab_power, tab_ampab_drive; §8.4.3 tab_ampab_cellstab, tab_ampab_compliance.
  • §8.3 tab_biasgen_tempco, tab_biasgen_line, tab_biasgen_trim, tab_biasgen_startup_time and the six per-corner fig_biasgen_*.
  • §8.10 tab_dacr2r12_ideal INL/DNL columns (not the scale columns); tab_dacr2r12_linereg quiescent current; tab_dacr2r12_loadreg and tab_dacr2r12_zout, both of which read a poly-set output impedance.
Stands as published.
  • Every Monte Carlo table and figure in §8.4.1, 8.5.6, 8.6.9, 8.8.3 and 8.10.2. castalia_pm_25 carries stat_res and mc_res; the measured process σ of 11.45 % on Rf is 3σ = 34 %, which is the corner box the corner set was missing. The MC sections have been the only honest process bound in the chapter.
  • §8.9 in full — tab_tiarprog_corners, fig_tiarprog_r_vs_code, note_tiarprog_spec. Its corner axis is res_ff/res_ss by construction.
  • §8.8 in full — tab_adc_corners, tab_adc_power. Extracted converter, no model-carded passive in the signal path.
  • §8.6.5 tab:pixtop-mux — no poly, MIM or MOM device in either DUT.
  • §8.3 tab_biasgen_dcop_free — already rebuilt on the free matrix; it is the reason this audit exists.
  • §8.4 tab_ampab_offset, §8.4.3 tab_ampab_tracking, §8.5.2 tab_px_ctrl_tracking / tab_px_ctrl_range — offset and tracking are matching- and swing-limited. A1's measured offset moves less when the passives are freed than the published box already allows.
  • §8.10 scale columns — zero scale, full scale, LSB. Ratiometric, identical to six digits.
  • §8.7 in full — it never claimed a corner, and eiscorner_20260825 has already supplied the corrected one.

Traps, for whoever repeats this. (1) Half of simarchive/tb_anatop_pixel_dacR2R12 is Monte Carlo — the Plan.2.Run.3/<n> decks carry mc1 montecarlo, and splicing a corner onto one launches a 200-sample sweep that looks exactly like a slow single run. Use Interactive.34/<n>; check with grep -c montecarlo first — and note that grep -c exits 1 on zero matches, which will short-circuit the && chain you were about to launch the job with. (2) pixchar_engine.set_corner maps tt to 37 °C and the process corners to 25 °C, because that is how the imported corners are defined; a bench whose own nominal is 25 °C then gets a temperature confound in its tt column. Compare against the orig run. (3) save=allpub on the archived amp bench wrote 292 MB per 10 000-point sweep. The archive keeps a two-column extract and deletes dc.dc; that is the third time this has cost an archive, and it belongs in the setup rather than the cleanup.
