Configuring the V-1…V-3 EIS decision benches

Written 2026-08-16 · Companion to afe_rev2_eis.html §10 (specs and expressions) — this file is the hands-on setup procedure. Library castalia, IC618, Spectre, models crn65gplus_2d5_lk_v1d0.scs per the simplan §0 global setup. The three benches decide whether EIS ships through the existing chain (Option B) or the copied leon engine.

V-1A2 flatness with Cf — extend tb_anatop_tia_amp_ab / TiaFbTB (no schematic edit)
V-2DAC as AC source — new view cloned from tb_anatop_pixel_dacR2R12 / DacTB, DUT swapped to anatop_dac
V-3A1 tracking — extend tb_anatop_ctrl_amp_ab / CellDriveTB (stb only) + a copied view of anatop_tb / PotFbTB with one added source
Two rules learned the hard way, apply to all three: (1) after ANY schematic edit, run Check and Save before netlisting — a stale extraction fails every run with OSSHNL-109; (2) a variable used only inside an output expression (f_ref, f_eis_max, …) is NOT discovered by Variables → Copy From Cellview — add it to the setup by hand or the outputs silently error.

V-1 · tb_anatop_tia_amp_ab / TiaFbTB

The bench already contains everything: ECS (randles_cell), R_F, C_F, IPRB_F (iprobe in the feedback path), I_WE (idc at WE), SRC_V_CM. Nothing is added to the schematic.

  1. Stimulus. Edit I_WE properties (q on the instance): set AC magnitude = 1. Leave the DC value as the bench has it (the AC analysis linearises about that operating point). With acm = 1 A, VF("/V_OUT") reads transimpedance in ohms directly — no division.
  2. Analyses.
    AnalysisFields
    acSweep: Frequency, Start 0.1, Stop 1M, Logarithmic, 20 pts/decade
    stbProbe Instance: /IPRB_F · Start 1 · Stop 100M · Logarithmic, 10 pts/dec. This is the loop measurement that was never run through the existing probe — it sizes Cf.
  3. Design variables (add by hand — see the rule box):
    VarValueRole
    f_ref10in-band reference frequency for normalisation
    f_eis_max10e3core-band edge
    f_eis_ext50e3extension edge
    rf_val35e3 ↔ 560e3on R_F; two-point sweep
    cf_val56p…560pon C_F; the sizing sweep
    rs_val, rct_val, cdl_valper simplan Randles seton ECS; Cdl = 100 nF is the PM worst case — it must be IN the set
    If R_F/C_F/ECS carry literal values today, repoint their CDF fields at these variables first (q → value → variable name), then Check and Save.
  4. Outputs. Enter in this order — each builds on the previous, never re-inline (house rule): 
    ztia          VF("/V_OUT")
ztia_mag      mag(ztia)
ztia_ref      value(ztia_mag VAR("f_ref"))
tia_gain_err  100 * (ztia_mag / ztia_ref - 1)
tia_err_fmax  value(tia_gain_err VAR("f_eis_max"))
tia_err_1k    value(tia_gain_err 1000)
tia_phase     phase(ztia)
tia_ph_fmax   value(tia_phase VAR("f_eis_max")) - value(tia_phase VAR("f_ref"))
tia_peak_db   dB20(ymax(ztia_mag) / ztia_ref)
pm_tia        phaseMargin(getData("loopGain" ?result "stb"))
    For bulk entry use the Outputs CSV round-trip (export the pane to CSV to get the exact column layout, append rows with these Name/Expression pairs, re-import) — the expressions inside maestro.sdb are not hand-editable, the CSV path is the supported bulk route.
  5. Specs (Outputs pane spec column): tia_err_fmax ∈ [−5, 5] on the Rf = 35 k rows; tia_err_1k ∈ [−5, 5] on the 560 k rows; tia_peak_db < 1; pm_tia > 60.
  6. Corners. tt/ss/ff/sf/fs from crn65gplus_2d5_lk_v1d0.scs plus the _res/_mim families (tt/ss/ff only — Rf is the on-chip R string in the real channel; the bench R_F is ideal, so R-corner sensitivity enters later through the string, note it in the readout).

V-2 · new view DacAcTB for anatop_dac

No existing bench drives anatop_dac (the 14-bit pattern DAC) dynamically — tb_anatop_pixel_dacR2R12/DacTB is the template but targets the 12-bit pixel DAC. Build once:

  1. Create the bench. Copy view tb_anatop_pixel_dacR2R12/DacTB → tb_anatop_dac_ac/DacAcTB (new cell so the pixel bench stays pristine). Swap DAC → castalia/anatop_dac; the code bus widens to A<13:0>, so replace the busset12 with a tb_utils/busset14 (the same cell PotFbTB uses for vp<13:0>). Keep POWER, En, output pin.
  2. Toggling stimulus — one bit, not an adder. 10 mV at 14 bits/2.5 V is 65.5 LSB; the clean bench equivalent is toggling bit 6 (64 LSB = 9.766 mV pp): set the busset14 codes to mid-scale (0x2000-ish) on all bits except A<6>, and drive A<6> from an analogLib/vpulse at the excitation rate (period 1/VAR("f_sq"), 50 %, rise/fall 1 ns, levels 0 / 2.5 — the DAC inputs are the 2.5 V domain). Wire it by deleting that one bit from the busset span and labelling the vpulse output A<6>.
  3. Analysis. tran, stop = 12/VAR("f_sq") (≥ 10 full cycles after the first two settle), strobe fine enough for the 100 µV band (conservative preset for the record run; moderate for iteration).
  4. Design variables. f_sq = 10e3 (then 50e3 for the extension run), t_edge = one rising-edge time in steady state, v_final = the settled post-edge value from a first exploratory run, settle_band = 100e-6, t_meas_lo/t_meas_hi = a ≥ 5-cycle window after cycle 2. (Freezing v_final from a measurement, then keeping the window fixed for every corner/sample, is the same no-self-referential-window rule the Maestro style section mandates.)
  5. Outputs. 
    vpat        VT("/Out")
vpat_err    abs(vpat - VAR("v_final"))
t_settle    cross(vpat_err VAR("settle_band") -1 "falling") - VAR("t_edge")
vpat_pp     peakToPeak(clip(vpat VAR("t_meas_lo") VAR("t_meas_hi")))
    cross() is legitimate here — vpat_err is guaranteed to enter the band; n = −1 takes the LAST crossing so pre-ring re-entries don't fake an early settle.
  6. Specs. t_settle < 5e-6 at f_sq = 10 k (< 1e-6 at 50 k); vpat_pp ∈ [9.668e-3, 9.864e-3] (9.766 mV ± 1 %).
  7. Corners incl. the _res family — the R-2R ladder is poly R, this is where its corner spread shows.

V-3 · CellDriveTB (stb) + PotFbAcTB (system)

Part a — A1 loop gain vs frequency, tb_anatop_ctrl_amp_ab/CellDriveTB

  1. No schematic edit — IPRB1 is already in the loop with ECS.
  2. stb: Probe /IPRB1, 1 Hz–100 MHz log. Sweep the DC set-point (SRC_V_CM/pattern variable) across the CV range — loop gain into the cell is operating-point dependent (the 78 dB → 13 dB precedent), so the spec must hold at the worst set-point, not the friendly one.
  3. Outputs / specs: 
    lg_a1       getData("loopGain" ?result "stb")
lg_mag_db   dB20(mag(lg_a1))
lg_fmax_db  value(lg_mag_db VAR("f_eis_max"))
    lg_fmax_db > 40 → Option B clean; 20–40 → RE-tap-to-SAR required (plan for this outcome); < 20 → Option B fails at 10 kHz.

Part b — composed tracking, copy anatop_tb/PotFbTB → PotFbAcTB

  1. Copy the view first (PotFbTB is the proven full-channel bench — CONTROLAMP, TIAAMP, PATTERNGEN/GNDGEN = real DACs, ECS, both iprobes; keep it pristine).
  2. One schematic edit: break the wire from PATTERNGEN's output to the v_pattern net and insert an analogLib/vsource in series: DC 0, AC magnitude 1. The DAC then sets the operating point and the vsource is the small-signal excitation — exactly the Option-B topology. Check and Save.
  3. Analyses: ac 0.1 Hz–1 MHz log 20/dec. Keep a tran available for the later firmware-shaped run (square on the DAC code per V-2) but the decision metric is the ac.
  4. Outputs / specs: 
    re_track      VF("/RE")
re_track_err  100 * abs(mag(re_track) - 1)
re_err_fmax   value(re_track_err VAR("f_eis_max"))
re_ph_fmax    value(phase(re_track) VAR("f_eis_max"))
z_chain       (VF("/RE") - VF("/WE")) / IF("/R_F/PLUS")
    re_err_fmax < 1; |re_ph_fmax| < 1. z_chain carries no spec — it is the quantity firmware will compute; sanity-check its plateau values against the Randles variables by eye.
  5. Corners: simplan set + Randles set. The bias generator is inside this loop — remember corners hide a self-biased loop's real spread (1.2 % corners vs 12.5 % MC precedent), so once the nominal passes, run a small MC on re_err_fmax before trusting the margin — and verify the cross-output reference chain survives the FIRST MC run before reading any distribution.

Running and archiving

  • GUI: normal Maestro runs from the saved setups.
  • Headless: once a setup is saved, ~/chips/castalia/skill/eis_headless_run.sh -c <cell> -l castalia -v maestro -t <Test> -o <outdir> runs it without the GUI and prints the evaluated outputs (recipe: skill/eis_headless_run.md). -L lists test names — check them, saved names sometimes differ from view names (the PGA bench's test is TypWBias, not TypWBiasTB).
  • Archive every decision run to ~/chips/castalia/simarchive/ — Maestro rotates results away.
  • Decision gate (from §10 of the main doc): V-1 ∧ V-2 ∧ V-3 pass at 10 kHz → freeze Option B; V-3 in the 20–40 dB band → Option B + RE tap; multiple fails → the leon engine returns to the floorplan and the bias-global collision gets resolved first.
